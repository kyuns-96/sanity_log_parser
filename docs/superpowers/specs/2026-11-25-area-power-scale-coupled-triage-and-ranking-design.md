## 1. 문제 정의와 원인

### 현상
전력 절대값이 매우 작은 하위 인스턴스(예: `0.01 mW → 0.06 mW`, 실제 변화량 `+0.05 mW`)가 단순 상대 변화율(`Δ% = +500%`) 때문에 큰 사고처럼 강조되어, 실제 수 mW씩 증가한 핵심 블록보다 시선을 빼앗고 정렬·AI 후보 목록을 오염시킨다.

### 현재 구조의 3가지 원인
1. **임계값 비대칭 (`Area`만 하한선이 있고 `Power`는 없음)**
   - 표(`Area ≥ 50`)와 AI 후보 선별(`min_area = 50`) 모두 면적 최소 기준만 존재한다.
   - 실제 설계에서는 면적은 크지만 클럭 게이팅·대기 로직이라 전력만 `0.01 mW` 수준인 인스턴스가 흔하며, 이들이 면적 기준을 통과한 뒤 큰 `Δ%`를 발생시킨다.
2. **시각 막대(`change-bar`)와 기본 정렬이 기여도(`Δ mW`)가 아닌 단순 `|Δ%|`에만 묶여 있음**
   - 셀 배경 막대 길이가 `min(100, |Δ%|)`로 계산되어, `50 → 60 mW (+20%, +10 mW)`는 막대가 20%만 차는 반면 `0.01 → 0.06 mW (+500%, +0.05 mW)`는 100% 경고 막대로 표시된다.
   - 기본 화면인 좌우 비교(`split`) 모드에는 `Δ(절대량)` 열이 없어 `Δ mW` 내림차순 정렬이 불가능하다.
3. **단순 절대값 컷오프의 한계**
   - 반대로 `|Δ Power| < 0.3 mW`처럼 고정 컷오프로 일괄 제외하면, 소형 Always-On 모듈이나 FSM에서 클럭 게이팅(ICG) 누락 등으로 `0.02 mW → 0.25 mW`(10배 이상 폭증) 같은 **실제 국소 설계 버그**까지 함께 묻힌다.

### 동시에 달성해야 할 두 가지 질문
- **예산 관점 (Macro)**: *"이번 버전에서 블록/칩 전체 파워와 면적 예산을 실제로 누가 늘렸는가?"* → 척도: **절대 변화량(`+Δ mW`, `+Δ Area`) 및 전체 대비 기여도**
- **이상 발굴 관점 (Micro)**: *"전체 비중은 작더라도 자기 체급 대비 비정상 배수로 급증한 고장 인스턴스가 있는가?"* → 척도: **노이즈 바닥을 반영한 체급 연동 변화율**

## 2. 핵심 수식: 체급 연동 변화율 (Damped Relative Change)

작은 분모($B \to 0$)에서 비율이 발산하는 문제를 `if/else` 절벽 없이 연속적으로 해결하기 위해 분모에 **완충 상수(쿠션) $\varepsilon$**을 더한 **체급 연동 변화율**을 메인 판단·정렬 척도로 사용한다.

$$\text{체급 연동 변화율}(\%) = \frac{C - B}{B + \varepsilon} \times 100\%$$

판정 기준치 $p$(예: $10\% = 0.10$)에 대해 위 식을 풀면 다음과 정확히 동치다:

$$\frac{\Delta}{B + \varepsilon} \ge p \quad \Longleftrightarrow \quad \Delta \ge (B \times p) + \delta_0 \qquad (\text{단, 기본 노이즈 턱 } \delta_0 = p \times \varepsilon)$$

- **대형 인스턴스 ($B \gg \varepsilon$)**: $\varepsilon$의 영향이 사라져 기존 단순 `Δ%`와 사실상 동일하게 동작한다.
- **중형 인스턴스 ($B \approx \varepsilon$)**: 경계 구간의 미세 흔들림을 완충한다.
- **극소형 인스턴스 ($B \ll \varepsilon$) 및 신규 전력 발생 ($B = 0$)**: 0 나눗셈 오류 없이 자연스럽게 **절대 변화량 기준($\Delta \ge \delta_0$)**으로 전환되어, 수십 µW 잔물결은 걸러내고 비정상 폭증(`0.02 → 0.25 mW`)은 살려낸다.

## 3. 기본 노이즈 턱($\delta_0$) 및 최소 면적(`min_area`) 기준 설정

전력(`mW`)은 같은 블록이라도 코너(전압·온도)와 주파수에 따라 수 배~십수 배 달라지므로, 코드에 단일 고정 `mW` 상수를 박지 않고 **실행 데이터의 스케일에 자동 연동**한다.

### 3.1 두 가지 자동 스케일링 방식

1. **루트 대비 비율(`s%`) 연동 방식**
   - `min_area`를 현재 비교 대상 루트 면적의 `s%`(예: `0.1% ~ 0.5%`), 전력 기본 노이즈 턱 $\delta_0$를 루트 Total Power의 `s%`로 대칭 연동한다.
   - 수학적으로 Logic Area당 전력 밀도($\rho = \text{Root Power} / \text{Root Logic Area}$)에 기준 면적($s \times \text{Root Logic Area}$)을 곱하면 면적이 약분되어 $\delta_0 = s \times \text{Root Power}$와 일치한다.
   - `chip_top`에서는 블록 단위 거시 변화를, 개별 블록 비교에서는 블록 내부 서브모듈 변화를 자동으로 줌인(Zoom-in)해 보여준다.
   - **SRAM 누락 방지**: 행 표시 및 면적 하한 판정 시에는 `Logic Area = 0`인 대형 SRAM 매크로가 숨겨지지 않도록 면적 크기를 `max(Total Area, Logic Area)`(기준·현재 중 큰 쪽)로 평가한다.
2. **Logic 전력 밀도 × 기준 면적($A_{\text{ref}}$) 방식**
   - 풀칩 트리 탐색과 서브블록 단독 비교에서 **동일 하위 인스턴스에 완전히 동일한 판정 기준**을 유지해야 할 때는, 양쪽 실행의 평균 Logic 전력 밀도 $\bar{\rho} = \text{Total Power} / \text{Logic Area}$에 고정 기준 면적(예: `500 ~ 1,000 µm²`)을 곱해 $\delta_0 = \bar{\rho} \times A_{\text{ref}}$로 산출한다.

### 3.2 합성 수치 시뮬레이션 예시

합성 블록(`Logic Area = 700,000 µm²`, `Total Power = 70.0 mW`, 즉 `1,000 µm²`당 평균 `0.10 mW`)에서 판정 기준 $p = 10\%$일 때 비율 `0.1%`와 `0.5%`의 동작 비교:

| 하위 인스턴스 변화 (합성 예시) | 절대 변화 `Δ` | 단순 `Δ%` | **`0.1%` 연동**<br><small>(`min_area=700µm²`, `δ₀=0.07mW`, `ε=0.70`)</small> | **`0.5%` 연동**<br><small>(`min_area=3,500µm²`, `δ₀=0.35mW`, `ε=3.50`)</small> |
|---|---:|---:|---|---|
| 극미세 노이즈 (`0.002 → 0.015 mW`) | `+0.013 mW` | +650.0% | `+1.9%` (제외) | `+0.4%` (제외) |
| 미소 흔들림 (`0.010 → 0.060 mW`) | `+0.050 mW` | +500.0% | **`+7.0%` (제외)** | **`+1.4%` (제외)** |
| 소형 급증 — ICG 깨짐 등 (`0.020 → 0.250 mW`) | `+0.230 mW` | +1150.0% | **`+31.9%` (포착)** | `+6.5%` (제외) |
| 소형 대폭증 (`0.050 → 0.500 mW`) | `+0.450 mW` | +900.0% | **`+60.0%` (포착)** | **`+12.7%` (포착)** |
| 중형 증가 (`2.00 → 2.50 mW`) | `+0.500 mW` | +25.0% | **`+18.5%` (포착)** | **`+9.1%` (경계)** |
| 대형 증가 (`15.0 → 17.0 mW`) | `+2.000 mW` | +13.3% | **`+12.7%` (포착)** | **`+10.8%` (포착)** |

- **운영 가이드**: 국소 이상 발굴까지 촘촘히 챙기는 기본값으로는 **`0.1% ~ 0.2%`**가 적합하고, 블록 예산 영향 위주로 굵직하게 요약할 때는 **`0.5%`**가 적합하다. 프로젝트/화면 설정에서 비율(또는 직접 지정 값)을 조정할 수 있게 열어둔다.

## 4. Hierarchy 비교 표(UI) 설계

1. **원시 측정값·단순 비율의 투명성 유지**
   - 셀에 적히는 `Δ%` 숫자를 설명 없이 보정값으로 덮어쓰면 `기준`·`현재` 숫자와 암산이 맞지 않아 계산 오류로 오해받는다.
   - 원시 수치(`기준`, `현재`, `Δ`, `단순 Δ%`)는 그대로 유지하되, **강조 여부·막대 길이·기본 변화 정렬**을 체급 연동 기준으로 구동한다(마우스 오버 툴팁이나 상세 바에 체급 연동 점수를 병기 가능).
2. **배경 막대(`change-bar`)와 글자 강조의 역할 분리**
   - **배경 막대 길이**: 단순 `|Δ%|` 대신 **루트 전체 값 대비 절대 기여도(`|Δ| / Root`)**로 스케일링한다. `0.01 → 0.06 mW`는 막대가 그려지지 않고, 실제로 전체 파워를 움직인 큰 인스턴스만 막대가 길게 표시된다. (단, Vth·Drive 등 비율 지표의 `Δ%p`는 기존 스케일 유지)
   - **글자 색상(`up`/`down`)**: 체급 연동 변화율이 노이즈 기준 미만인 미소 변화는 경고색을 빼고 흐린 회색(`muted`)으로 톤다운한다.
3. **좌우 비교(`split`) 모드의 변화 열 전환 토글**
   - 툴바(또는 변화 헤더)에 **`Δ%` ↔ `Δ(절대량)`** 전환 스위치를 제공해 열 개수를 늘리지 않고도 기본 좌우 비교 상태에서 바로 `Δ mW` / `Δ Area` 크기순 정렬과 스캔이 가능하도록 한다.
   - 변화율 정렬 시에는 미소 분모 노이즈가 최상단을 덮지 않도록 **체급 연동 변화율 순 정렬**을 지원한다.

## 5. AI 후보 선별 및 결과 메일 ‘이중 랭킹(Dual Top-10)’ 구조

단일 임계값 방식은 리비전에 따라 알람이 수백 개 폭주하거나 반대로 0건이 되는 편차가 크다. 메일과 요약 리포트에서는 **고정 분량 안에 예산 주범과 국소 이상을 모두 담는 이중 Top-10 랭킹**을 사용한다.

### 5.1 선행 단계: 계층 Roll-up 중복 제거 (필수)
- 계층 트리에서는 말단 인스턴스 하나가 `+5 mW` 증가하면 상위 부모·조상 경로도 모두 `+5 mW` 증가한다. 그대로 랭킹을 매기면 하나의 원인이 상위 10칸 중 여러 칸을 독식한다.
- 기존 `triage.py`의 Roll-up 규칙(`ROLLUP_SHARE = 0.8`: 하위 후보들의 증가분 합이 부모 증가분의 80% 이상이면 부모를 접고 하위 실제 원인만 유지)을 랭킹 추출 전에 동일하게 적용해 **서로 독립적인 원인 인스턴스만** 후보 풀에 남긴다.

### 5.2 이중 랭킹 추출 규칙

| 순서 | 섹션 이름 (예시) | 정렬 기준 | 대상 조건 및 중복 처리 | 목적 |
|---|---|---|---|---|
| **1** | **절대 증가량 Top 10**<br>(`+Δ mW` / `+Δ Logic Area`) | `Δ = 현재 - 기준` 내림차순 | Roll-up 후 `Δ > 0`이며 최소 유의미 하한 이상인 항목 **최대 10개** | 전체 파워·면적 예산을 실제로 올린 주범 파악 |
| **2** | **체급 대비 급증 Top 10**<br>(국소 이상 징후) | `체급 연동 변화율 = Δ / (기준 + ε)` 내림차순 | **섹션 1에 이미 선정된 항목은 제외**하고, 나머지 중 체급 연동 기준치(예: `+10%`) 이상인 항목 **최대 10개** | 전체 비중은 작지만 자기 체급 대비 비정상 배수로 튄 모듈 발굴 |
| **별도** | **지정 관심 경로 (`watched_paths`)** | 등록 순서 | 변화 크기와 무관하게 별도 표기 | 담당자가 명시적으로 감시 등록한 핵심 경로 확인 |

### 5.3 조용한 리비전 처리 (`Up to 10`)
- 무조건 10줄을 채우지 않고 **최소 유의미 기준(예: 체급 연동 변화율 `+5% ~ +10%`)을 넘는 항목만 최대 10개(Up to 10)** 수록한다.
- 유의미한 증가 항목이 없으면 억지 순위표 대신 `"특이 증가 항목 없음"`으로 간결하게 보고해 리포트 신뢰도를 유지한다.
