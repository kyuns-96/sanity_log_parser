## 1. 문제 정의와 통합 배경

### 현상 (Area와 Power 공통)
절대 크기가 작은 하위 인스턴스에서 약간의 셀·전력 편차만 발생해도 단순 상대 변화율(`Δ% = (C - B) / B`)이 수백 %로 치솟아, 실제로 블록 예산을 크게 늘린 주범보다 더 심각한 경고처럼 보인다.
- **Power 예시**: `0.01 mW → 0.06 mW` (`+0.05 mW` 편차) → 단순 **`+500.0%`**, 셀 막대 100% 주황 경고
- **Area 예시**: `min_area = 50` 바로 위인 `60 µm² → 240 µm²` (`+180 µm²`, 버퍼 수십 개 수준) → 단순 **`+300.0%`**, 셀 막대 100% 주황 경고

### 현재 구조의 3가지 한계
1. **칼자르기 하한선(`min_area`)과 무하한선(`Power`)의 한계**
   - `Power`는 하한선이 아예 없어 Area가 크고 활동도가 낮은(클럭 게이팅·대기) 인스턴스의 미소 전력 변화가 그대로 노출된다.
   - `Area`도 `min_area = 50` 칼자르기 직후(`51 µm²~`)부터는 비율 폭발이 그대로 발생하며, 반대로 `min_area`를 수천 `µm²`로 크게 올리면 소형 제어 로직의 합성 폭증 사고(`100 → 1,800 µm²`)가 통째로 잘린다.
2. **시각 막대(`change-bar`)와 기본 정렬이 기여도(`Δ`)가 아닌 단순 `|Δ%|`에만 결합됨**
   - `50 → 60 mW (+20%, +10 mW)`는 막대가 20%만 차는 반면 `0.01 → 0.06 mW (+500%, +0.05 mW)`는 100% 막대로 표시된다.
   - 기본 화면인 좌우 비교(`split`) 모드에는 `Δ(절대량)` 열이 없어 `Δ` 크기순 정렬이 불가능하다.
3. **두 가지 엔지니어링 질문의 혼재**
   - **예산 관점 (Macro)**: *"블록/칩 전체 Area·Power 예산을 실제로 누가 늘렸는가?"* → **절대 변화량(`+Δ`) 및 루트 기여도**
   - **이상 발굴 관점 (Micro)**: *"전체 비중은 작아도 자기 체급 대비 비정상 배수로 튄 고장 모듈이 있는가?"* → **체급 연동 변화율**

## 2. 통합 수식: Area · Power · Cells 공통 체급 연동 변화율

비율(`%`) 지표(`Vth`, `Drive`, `CTS %`)를 제외한 **모든 양적(additive) 지표 $M$ (`Area`, `Gate Count(GE)`, `Power`, `Cells`)**에 동일한 **체급 연동 변화율(Damped Relative Change)** 공식을 적용한다.

$$\text{체급 연동 변화율}_M(\%) = \frac{C_M - B_M}{B_M + \varepsilon_M} \times 100\%$$

판정 기준치 $p_M$(기본 $10\% = 0.10$)과 **기본 노이즈 턱 비율 $s$**에 대해 완충 상수(쿠션) $\varepsilon_M$은 다음과 같이 자동 산출한다:

$$\delta_{0,M} = s \times \text{Root}_M, \qquad \varepsilon_M = \frac{\delta_{0,M}}{p_M} = \frac{s}{p_M} \times \text{Root}_M$$

판정 부등식을 풀면 다음과 정확히 동치다:

$$\frac{\Delta_M}{B_M + \varepsilon_M} \ge p_M \quad \Longleftrightarrow \quad \Delta_M \ge (B_M \times p_M) + \delta_{0,M}$$

### 이 통합 수식의 성질
1. **전 구간 연속성**: 대형 인스턴스($B_M \gg \varepsilon_M$)에서는 단순 `Δ%`와 동일하고, 극소형 인스턴스($B_M \ll \varepsilon_M$)에서는 자동으로 절대 변화량 기준($\Delta_M \ge \delta_{0,M}$)으로 전환되며, 신규 생성/활성($B_M = 0$)에서도 0 나눗셈 오류 없이 동일 척도로 점수화된다.
2. **코너·전압·주파수·블록 크기 자동 적응**: 별도의 `mW`나 `µm²` 상수를 추측할 필요 없이 각 실행의 루트 스케일에 맞춰 Area와 Power 기준이 동시에 맞춰진다.
3. **공정 간 Gate Count(`GE`) 불변성**: 면적을 `NAND2_D1` 단위 면적으로 나눈 `GE` 모드에서도 분자($B, C$)와 분모($\text{Root}$)가 동일한 단위로 변환되므로 `µm²` 기준과 `GE` 기준의 체급 연동 변화율이 100% 일치한다.

### 지표군별 기준 루트값($\text{Root}_M$) 매핑 규칙
- 기준·현재 양쪽 루트값이 모두 양수면 대칭성을 위해 평균값 $\frac{1}{2}(\text{Root}_{B} + \text{Root}_{C})$을 쓰고, 한쪽만 양수면 그 값을 사용한다.
- 하위 세부 지표가 작은 분모로 다시 폭발하지 않도록 **상위 총량 루트**를 공유한다:
  - `logic_area`, `cts_area`, `others_area` → **Root `logic_area`** (0이면 Root `total_area` 대체, 최소 물리 바닥 `50` 보장)
  - `total_area`, `sram_area`, `io_area` → **Root `total_area`** (SRAM 매크로가 Logic Area=0이어서 누락되는 현상 방지)
  - 모든 전력 지표(`pwr_*_mw`: total / internal / switching / leakage 전체) → **Root `pwr_all_total_mw`**
  - 모든 셀 개수 지표(`*_cells`) → **Root `total_cells`**

## 3. 기본 비율 선정 근거: 권장 기본값 **`s = 0.10%`** (`ε = 루트의 1.0%`)

판정 기준치 $p = 10\%$일 때 후보 비율(`0.05% ~ 0.50%`)을 풀칩·대형 블록·소형 블록 전 구간에서 검증한 결과, **`s = 0.10%` (기본 노이즈 턱 = 루트의 `0.1%`, 완충 쿠션 $\varepsilon$ = 루트의 `1.0%`)**를 기본값으로 채택한다.

### 3.1 왜 `0.05%`나 `0.50%`가 아닌 **`0.10%` (보조 권장 범위 `0.10% ~ 0.15%`)**인가?
- **`0.05%`의 문제 (과소 완충)**: `70 mW` 블록에서 $\delta_0 = 0.035\text{ mW}$에 그쳐 `0.01 → 0.06 mW (+0.05 mW)`가 `+13.9%`로 남아 미소 노이즈 제거에 실패한다.
- **`0.50%`의 문제 (대형 블록 과감쇠)**: $p = 10\%$일 때 쿠션 $\varepsilon = s / p$가 **루트 전체의 `5.0%`**까지 커진다. 그 결과 블록 전체의 14%를 차지하는 주요 서브블록이 `10.0 → 11.2 mW (+12.0%)` 증가해도 체급 연동 점수가 `+8.9% (< 10%)`로 눌려 탈락하며, 소형 모듈의 합성 사고(`100 → 1,800 µm²`)도 `+4.8%`로 묻힌다.
- **`0.10%`의 균형점 ($\delta_0 = 0.1\%$, $\varepsilon = 1.0\%$)**:
  - **소형 블록 (`50,000 µm² / 5 mW`)**: $\delta_0 = 50\text{ }\mu\text{m}^2\text{ / }0.005\text{ mW}$로 기존 `min_area = 50` 감각과 자연스럽게 일치한다.
  - **대형 블록 (`700,000 µm² / 70 mW`)**: 미소 노이즈(`+0.05 mW`, `+180 µm²`)는 확실히 탈락시키면서, 소형 실제 사고(`+0.23 mW`, `+1,700 µm²`)와 대형 서브블록 `+12%` 증가(`+11.2%`)를 모두 왜곡 없이 포착한다.
  - **풀칩 (`10,000,000 µm² / 1,000 mW`)**: $\delta_0 = 10{,}000\text{ }\mu\text{m}^2\text{ / }1.0\text{ mW}$로 탑 레벨 서브시스템 예산 단위에 자동 정렬된다.

### 3.2 합성 블록(`Logic Area = 700,000 µm²`, `Total Power = 70.0 mW`) 검증표 ($p = 10\%$)

기본값 **`s = 0.10%`** 적용 시 자동 산출값:
- **Area**: 기본턱 $\delta_{0,\text{area}} = 700\text{ }\mu\text{m}^2$, 쿠션 $\varepsilon_{\text{area}} = 7{,}000\text{ }\mu\text{m}^2$
- **Power**: 기본턱 $\delta_{0,\text{power}} = 0.070\text{ mW}$, 쿠션 $\varepsilon_{\text{power}} = 0.700\text{ mW}$

| 구분 | 하위 인스턴스 변화 (합성 예시) | 절대 변화 `Δ` | 단순 `Δ%` | **`s=0.10%` 체급 연동** | 판정 (`≥10%`) | 참고: `s=0.50%`일 때 |
|---|---|---:|---:|---:|---|---|
| **Power** | 극미세 노이즈 (`0.002 → 0.015 mW`) | `+0.013 mW` | +650.0% | **`+1.9%`** | 노이즈 제외 | `+0.4%` (제외) |

## 4. Hierarchy 비교 표(UI) 설계

1. **원시 측정값·단순 비율 보존**
   - 셀 텍스트에 적히는 `기준`, `현재`, `Δ`, `단순 Δ%` 숫자는 왜곡하지 않는다(`기준`·`현재`와의 암산 일치 유지). 대신 **색상 강조·막대 길이·변화율 정렬**을 체급 연동 변화율로 구동하고, 툴팁/하단 상세에 체급 연동 점수를 함께 표시한다.
2. **배경 막대(`change-bar`)와 글자 강조의 역할 분리 (Area · Power 공통)**
   - **배경 막대 길이**: 단순 `|Δ%|` 대신 **루트 대비 절대 기여도(`|Δ_M| / Root_M`)**로 스케일링한다. `0.01 → 0.06 mW`나 `60 → 240 µm²`에는 긴 막대가 생기지 않고, 실제로 전체 면적·전력을 움직인 큰 인스턴스만 막대가 차오른다. (비율 지표 `Δ%p`는 기존 스케일 유지)
   - **글자 색상(`up`/`down`)**: 체급 연동 변화율 미달(`|체급 연동 변화율| < p_M`)인 미소 변화는 경고색을 빼고 흐린 회색(`muted`)으로 톤다운한다.
3. **좌우 비교(`split`) 모드의 변화 열 전환 토글 및 정렬**
   - 툴바에 **`Δ%` ↔ `Δ(절대량)`** 전환 스위치를 두어 열 개수를 늘리지 않고도 좌우 비교 화면에서 바로 `Δ Area` / `Δ mW` 크기순 정렬과 스캔을 지원한다.
   - `Δ%` 열 정렬 시에는 미소 분모 노이즈가 상단을 덮지 않도록 **체급 연동 변화율 순 정렬**을 기본 적용한다.

## 5. Dominant Sub-block 가시화 · 집중도 기반 Roll-up · 이중 Top-10 구조

최상위(루트)가 증가했을 때 **"어느 1단계 sub-block이 전체 증가를 주도했는가(큰 그림)"**와 **"실제 뿌리 원인이 어디인가(세부 원인)"**가 서로 가리지 않도록 **① 1단계 직속 기여도 요약 → ② 집중도 기반 스마트 Roll-up → ③ Area·Power 대칭 이중 Top-10** 순서로 구성한다.

### 5.1 최상단 고정 요약: 1단계(Depth-1) 직속 Sub-block 기여도 분해
- **기존 문제**:
  - 곧바로 말단 Roll-up 결과만(알파벳순 등으로) 나열되어, 루트 `+10%` 증가를 어느 1단계 sub-block이 주도했는지 한눈에 보이지 않는다.
  - 또한 비중이 큰 거대 sub-block이 자체 증가율 `+9.8%`(`< 10%`)로 전체 증가의 75% 이상을 차지한 경우 이상 후보에서 빠져 큰 그림에 사각지대가 생긴다.
- **설계 규칙**:
  - 임계값(`10%`)이나 Roll-up 여부와 무관하게, 루트 전체가 증가(`Δ_root > 0`)했을 때는 **루트 직속(Depth-1) sub-block들의 `+Δ` 크기순 상위 3~5개와 전체 증가분 대비 점유율(`Δ_child / Δ_root × 100%`), 나머지 블록 합계**를 화면 요약과 메일 최상단에 항상 먼저 표시한다.
  - 합성 예시 (`Total Power: 70.0 → 77.0 mW`, `+7.0 mW / +10.0%`):
    - `1. u_npu`: **`+5.8 mW`** (전체 증가의 **83%**) · `30.0 → 35.8 mW (+19.3%)`
    - `2. u_cpu`: **`+1.0 mW`** (전체 증가의 **14%**) · `25.0 → 26.0 mW (+4.0%)`
    - `기타 5개 블록 합계`: `+0.2 mW` (`3%`)

### 5.2 집중도 기반 스마트 Roll-up (분산 희석 역설 방지)
- **기존 단순 합계 Roll-up(`하위 합계 ≥ 80%`)의 ‘분산 희석(Fragmentation)’ 역설**:
  - 하위 자식 1개가 증가하면 부모·조상 경로도 함께 증가하므로 조상 중복 제거는 필수다.
  - 그러나 예를 들어 1위 주범 `u_npu`(`+6.0 mW`) 내부의 파이프라인 블록 **20개가 `+0.30 mW`씩 고르게** 오른 경우, 단순 합계(`6.0 mW ≥ 80%`) 규칙만 적용하면 `u_npu(+6.0 mW)`를 지우고 `+0.30 mW`짜리 말단 20개로 쪼개버린다. 그 결과 다른 단일 모듈(`+0.50 mW`)들에 밀려 **정작 `+6.0 mW`를 올린 1위 주범 계열이 절대량 Top 10에서 통째로 탈락**하는 역설이 발생한다.
- **집중형 vs 분산형 분기 규칙 (`Logic Area` · `Total Power` 각 지표별 독립 적용)**:
  1. **집중형 (Concentrated — 하위 드릴다운)**:
     - 증가한 하위 자식 중 **상위 1~2개 자식의 `Δ` 합계가 부모 증가분의 `≥ 75%`(예: 70~80%)를 설명**할 때만 실제 원인이 특정 자식에 집중된 것으로 보고 부모를 접어 해당 자식으로 내려간다.
     - 드릴다운된 말단 항목에는 소속 1단계 sub-block 컨텍스트(예: `u_npu ▸ ...`)를 함께 유지한다.
  2. **분산형 (Distributed — 상위 블록 유지 + 하위 요약 병기)**:
     - 전체 하위 합계는 크더라도 **3개 이상의 다수 자식에 고르게 분산**되어 상위 1~2개만으로는 부모 증가분의 `75%`에 못 미치면(클럭/활동도/공통 합성 제약 등 블록 전반 원인), 말단으로 쪼개지 않고 **부모 블록(`u_npu`, `+6.0 mW`) 자체를 후보 및 Top 10 순위에 그대로 유지**한다.
     - 대신 해당 카드와 메일 항목 아래에 **지표별(`Area` / `Power` 각각) 하위 주요 기여 자식 Top 3 + `외 N개 분산`** 요약을 한 줄로 병기한다. *(기존 `triage.py`에서 `top_children`이 Area 증가분으로만 정렬되고 UI·메일에 출력되지 않던 한계를 함께 수정한다.)*

### 5.3 지표별 이중 랭킹 추출 규칙 (`Logic Area` · `Total Power` 대칭 적용)

위 스마트 Roll-up을 거친 독립 원인 풀에서 각 지표(`Logic Area`, `Total Power`)마다 아래 두 랭킹을 추출한다:

| 순서 | 섹션 구성 | 정렬 기준 | 대상 조건 및 중복 처리 | 목적 |
|---|---|---|---|---|
| **1** | **절대 증가량 Top 10**<br>(`+Δ Logic Area`, `+Δ Power`) | `Δ_M = C_M - B_M` 내림차순 | 스마트 Roll-up 후 `Δ_M > 0`이며 최소 유의미 기준(예: 체급 연동 `+5%`) 이상인 항목 **최대 10개** | 전체 면적·전력 예산을 올린 핵심 주범 파악 (분산 증가 상위 블록 포함) |
| **2** | **체급 대비 급증 Top 10**<br>(국소 이상 징후) | `체급 연동 변화율_M` 내림차순 | **섹션 1에 이미 선정된 항목은 제외**하고, 나머지 중 판정 기준치(예: `+10%`) 이상인 항목 **최대 10개** | 전체 비중은 작지만 자기 체급 대비 비정상 배수로 튄 모듈 발굴 |
| **별도** | **지정 관심 경로 (`watched_paths`)** | 등록 순서 | 변화 크기와 무관하게 별도 표기 | 담당자가 명시 등록한 감시 대상 확인 |

### 5.4 조용한 리비전 처리 (`Up to 10`)
- 변화가 거의 없는 리비전에서 무의미한 미세 항목으로 10칸을 채우지 않고, 기준을 넘는 항목만 **최대 10개(Up to 10)** 표시한다(없으면 `"특이 증가 항목 없음"` 한 줄로 요약).
