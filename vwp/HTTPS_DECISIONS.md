# VWP 제출 정책 — 토큰 없는 내부 접수

2026-10-27 사용자 확정에 따라 **VWP 제출용 개인 토큰을 사용하지 않는다.** 이전의 OA SSO 토큰 발급·폐기/8시간·5개 정책은 폐기된 설계다. 사내 AI에게 해당 발급기나 검증 SDK 구현을 요청하지 않는다.

현재 제공한 동작은 [HTTPS 제출 안내](HTTPS_SUBMISSION.md)를 따른다.

1. VWP는 bridge에만 HTTPS로 접속한다. 사용자별 자격증명을 요구하지 않으며 배포 담당자가 허용한 내부 출발 IP에서 접수한다.
2. 원본은 [VWP private DB](DB_ORIGINALS.md)에 보관하고 파싱 중에만 임시 복원한다.
3. VWP OS 계정 표시는 신원 미확인 자료다. 입력 username이나 actor로 OA 사용자를 가장하거나 권한을 부여하지 않는다.
4. OA에서 로그인한 현재 블록 OWNER가 정확한 예상 검사 범위·누락·제외를 확인하고 접수를 확정한다. 확정자·시각·범위/입력 해시·사유를 DB에 기록한다. TOP은 조회 범위만 가진다.
5. 확정 전에는 보고서를 검토/모델 입력으로 공개하지 않는다. 반려/수신 실패는 원본과 근거를 보존한다. 범위 확정과 검사 PASS/AI·사람 판정 완료는 구분한다.
6. 기존 SSO/RBAC·AI 모델 인증은 유지한다. 새 모드에 VWP 제출 토큰이나 별도 OA↔bridge HTTP 통로가 필요하지 않다.

CLI schema 3·bridge schema 4를 함께 선택한다. 기존 Bearer 설정과 폴더 경로는 호환용이며 오류 시 자동 모드 변경은 없다. 010까지의 기존 네 DB 테이블/메시지로 구현하고 추가 SQL/계정/GRANT는 요구하지 않는다. 실제 회사 provider/parser·SSO/OWNER·DB/TLS/네트워크는 현장에서 연결·검증한다.
