# OA 검토 대시보드

React·TypeScript·Vite·Tailwind CSS와 Radix 기반 Shadcn Studio 구성 요소를 사용하는 한국어 검토
화면입니다. 외부 폰트·CDN·분석 서비스 호출 없이 로컬 Pretendard·Geist Mono와 시스템 폰트를 사용합니다.
서버 API와 같은 출처에서 제공하며, 접근 토큰은 탭 메모리에만 보관합니다.

프로젝트·담당자·블록별 버전·PoR의 업무 규칙과 운영 구현안은
[요구사항 15절](../../requirement.md#dashboard-domain-spec)을 따릅니다. 아래는 현재 데모의 사용법과 구현 범위입니다.

운영 SSO의 AI 작업 화면은 **`/?page=workbench`**, 업무 API는 **`/api/workbench/*`**입니다.
**`/workspace`**와 `/workspace/api/*`는 별도로 실행하는 독립 합성 앱이며 운영에 자동 마운트하지 않습니다.
로그인한 사용자의 프로젝트/블록/버전/검사/PoR을 각 환경의 서버 상태로 연결합니다.
PoR 지정과 사유·지정자·시각·개정은 PostgreSQL에 저장하며 새로고침하거나 TOP 계정으로 조회해도 유지됩니다.
검사의 **보고서 보기 → 사용자 판정·AI review**에서 독립 사용자 판정과 사유·재사용 조건을 저장합니다.
sanity item의 보고서 행에서 **검토 시작**을 누르면 **1. 로그 분류 → 2. 그룹별 판정**을 순서대로 진행합니다.
단일 report의 평균 10,000건·100,000건 이상 로그를 서버에서 저장·편집하고 그룹 25개·원문 50건씩 조회합니다. 참고 분류 작업은 저장한 위치에서 이어갈 수 있습니다. 두 규모는 업무상 상한이 아닙니다.
OA 모델 호출은 전체 입력이 설정 한도에 들어가는 대상에 제공하며, 모델의 대용량 분할·통합은 후속 구현입니다. 화면 페이지 크기는 AI가 읽는 입력 범위를 뜻하지 않습니다.
재분류된 그룹의 이전 판정은 재검토 대상으로 표시하며, 기존 보고서 단위 판정 이력은 별도로 보존합니다.
원본 FAIL에도 사용자 PASS를 기록할 수 있습니다. 운영 OA AI 호출·직접 근거 판정·확정 사례 검색은 [OA 실행 계약](../AI_RUNTIME.md)을 따르며 실제 사내 API 연결과 판단 품질 검증은 사내에서 진행합니다.
`gpt-6-luna` 실제 호출 결과와 사람 정정 피드백을 확인하는 [별도 합성 mock](../WORKSPACE.md#codex-모델을-사용하는-합성-mock-시험)을 추가했습니다. 지정된 합성 mock report의 **AI로 그룹 만들기**는 실제 모델을 호출합니다. 기존 그룹을 다시 만들려면 **설정과 이전 기록 → AI로 그룹 다시 만들기**를 엽니다. **참고 엔진으로 초안 생성**·판정 제안과 구분해 출처/진행 상태를 표시합니다.
실행·테스트 계정·보호 경계는 [WORKSPACE.md](../WORKSPACE.md)를 읽습니다. `?demo=1`은 같은 최신 워크스페이스 UI를 사용하는 메모리 데모입니다.
운영 로그인·권한 신청·관리자·프로젝트/블록·버전/PoR·검사 대장·검토 화면에 승인된 Shadcn Studio 구성을 적용합니다.
공통 테마는 밝은 회색 바탕과 차콜 강조색 `#272b35`이며, PASS/FAIL/보류는 각각 별도의 의미 색상으로 표시합니다.
분류 검토에서는 로그 손잡이를 왼쪽 그룹으로 끌어 소속을 변경합니다. 여러 로그 선택과 새 그룹 분리, 키보드·터치 이동도 지원합니다.
검토 화면은 **프로젝트·보고서 맥락 / 그룹 목록 / 로그 표·선택 원문 / 분류 근거·사용자 판정**의 네 영역으로 구성합니다.
그룹 순번은 현재 분류 개정의 그룹 순서이며 검색·필터·페이지 이동으로 다시 매기지 않습니다. 재분류/병합으로 구성이 바뀌면 순서도 바뀔 수 있으며, 그룹 식별자나 고정 분류 사전으로 쓰지 않습니다.
로그는 서버에서 50건씩 조회하며 행 선택(Enter/Space 포함)과 이동할 로그의 체크박스 선택을 구분합니다.
로그 표는 기본 34px(휴대폰 40px) 높이의 한 줄 행으로 대상·요약을 표시합니다. 긴 값은 말줄임하며 전체 원문·로그 ID·파싱 필드는 선택 원문 패널에서 확인합니다.
데스크톱에서는 제목과 단계·동작 버튼을 한 줄에 배치하고, 원문 패널은 기본 124px로 제한해 로그 목록이 남은 화면 높이를 사용합니다. 목록의 열 제목은 내부 스크롤 중에도 고정되며, 긴 원문과 파싱 필드는 원문 패널 안에서 스크롤합니다.
최초 조회에는 스피너와 뼈대 행을 표시합니다. 검색·페이지 변경 중에는 기존 목록과 원문을 흐리게 표시하고 선택·이동·복사를 잠시 막습니다. 조회 상태는 `aria-busy`와 상태 메시지로도 전달합니다.
모바일에서는 영역을 세로로 연결하고 원본 도구 결과·AI 제안·사용자 판정을 모두 표시합니다. 전문 용어를 유지하며 긴 근거·대표 로그·출처·이력·상세 집계·재사용 설정은 펼쳐서 조회합니다.
**분류 확정 · 판정 시작**으로 전체 그룹의 유효한 근거 초안을 일괄 채택하고 분류를 확정합니다. 전체 메모는 선택 사항입니다.
판정은 **PASS / FAIL / 보류**와 **판정 근거**를 기록합니다. 보류 그룹이 남으면 완료로 표시하지 않습니다.
선택형 **이번 판정을 규칙 예외로 기록**을 켜면 예외 대상 규칙·예외 사유·성립 조건을 함께 저장합니다. 예외도 다음 AI의 참고 사례가 되며, 다음 report에서는 조건을 다시 검토합니다. 예외 체크는 자동 PASS나 원본/분류 미완료의 면제가 아닙니다.
**AI 참고 허용 체크는 없습니다.** 모든 프로젝트·블록·revision·ECO의 확정 지식이 관련 참고 후보가 되며 AI가 출처와 조건 차이를 비교합니다. 원문 조회 권한은 그대로 유지하고 참고 사례에는 과거 원문 대신 사람이 확정한 그룹·판정·근거·예외와 출처를 표시합니다. 기존 참고 엔진의 조건 적용 승인은 일반 판정 편집에서 보존하고 예외·보류로 변경해 저장할 때 해제해 이전 이력에 남깁니다.
일반 버튼은 마우스를 올리면 색·테두리·그림자가 부드럽게 바뀌며 동작 버튼은 1px 떠오릅니다. 체크박스·단계·탭·로그 이동 손잡이와 비활성 버튼은 위치를 유지합니다. 터치 환경과 모션 감소 설정에서는 이동 효과를 적용하지 않습니다.
첫 방문·완료 동선과 모바일/읽기 전용 검증은 합성 QA 서버에서 `npx playwright test --config playwright.guidance.config.ts`로 실행합니다. 외부 모델은 호출하지 않습니다.

빌드 기준은 **Node 20.18.0**이다. Vite 6.4.4와 React 플러그인 4.7.0을 고정하고,
lockfile로 하위 의존성도 고정한다. Node 버전 관리 도구를 쓰면 이 디렉터리의 `.nvmrc`를 적용한다.
회사 Docker 구성은 [Docker 실행 안내](../docker/README.md)를 따른다.

CI가 판정 코드를 민감정보로 탐지할 때는 [민감정보 탐지 대응 기준](CI_TROUBLESHOOTING.md)을 따른다. 판정 문자열과 API·DB 계약은 유지하고 상태 선택 분기를 명확한 조건문으로 작성한다. 검사 억제나 실제 비밀값을 감추는 변경은 하지 않는다.

```sh
cd oa/dashboard
npm ci --engine-strict
npm run build
```

`dist/`를 OA 서버가 제공합니다. 서버 실행과 접근 토큰 발급은 상위 OA 문서를 참고합니다.
프런트엔드에 서버 토큰, DB 비밀번호나 연결 문자열을 넣지 않습니다. 브라우저 저장소나
URL에 인증 토큰을 기록하지 않으며 새로고침 후 다시 로그인해야 합니다.

개발 시 `npm run dev`는 `127.0.0.1:5173`에서만 수신하고 `/api`를 로컬
`127.0.0.1:8000`으로 전달합니다. 사내망 배포 시 의존성을 사전에 준비하고
`npm ci`와 빌드를 실행할 수 있는 오프라인 환경을 구성해야 합니다.

두 로그인 화면의 **데모 둘러보기**, `/?demo=1` 또는 **`/workspace?demo=1`**에서 최신 워크스페이스 데모를 엽니다.
서버용 `Workspace`·로그 분류·그룹 판정 컴포넌트를 그대로 사용하며, 명시적인 데모 요청에만 별도의 합성 메모리 어댑터를 연결합니다.
데모에서는 API·SSO·DB·AI를 호출하지 않으며 변경 내용을 현재 탭 메모리에만 저장합니다.
API 장애·인증 실패 시 오류를 표시하고 자동으로 데모로 바꾸지 않습니다.

기본 계정은 `user04`이며 상단 **데모 계정**에서 담당자와 TOP의 조회 범위를 비교합니다.
프로젝트·블록 → PRE/POST·버전·ECO → sanity 항목·보고서 → **검토 시작**에서
**그룹 초안 만들기 → 로그 이동·분리·병합 / 근거 검토 → 분류 확정 · 판정 시작 → 사용자 판정**을 체험합니다.
블록별 PoR 지정·변경 이력, 항목별 검색·필터·페이지, 합성 원문 다운로드도 제공합니다.
같은 탭에서 계정을 전환하면 데모 변경을 공유하며, 새로고침하면 계정과 변경이 모두 초기화됩니다.
각 블록의 최신 `NET_002` POST / `chip_finish`에는 합성 검사 38개(GCA 28·VC LP 5·SpyGlass 5)가 있습니다.
이전 `NET_001` POST에는 14개가 있으며 PRE와 `eco01`은 미수신 예시입니다. 부분 해석·미수신 보고서를 완료로 표시하지 않습니다.
합성 로그의 필드 값으로 만드는 데모 초안은 실제 파서·참고 사례 엔진·AI의 동작 검증 자료가 아닙니다.
최신 UI와 데모의 분리는 아래 테스트로 확인합니다.

```sh
SANITY_DASHBOARD_TEST_PORT=5180 npx playwright test e2e/workspace-demo.spec.ts
```

기존 번들 검토 대장은 **`/?demo=1&flow=legacy`**에서 유지합니다. 상단 **다른 예시**에서
이전 검토 대장·GCA 보고서·프로젝트 담당자·버전 데모를 열 수 있습니다.

1,000개 report parser 미리보기는 `/?demo=1&dataset=reports`에서 엽니다. 이용자 10명, 프로젝트 3개,
각 프로젝트의 CPU/GPU/DDR 3개 블록을 가정한 합성 데이터입니다. GCA·VC LP·SpyGlass의 초기 파서를 통해
실제 독립 PostgreSQL에 넣고 OA 수신을 확인한 **읽기 전용 스냅샷**을 표시합니다. DB와 AI를 실시간 호출하지 않습니다.
가상 계정의 담당 범위 전환, 도구·결과 필터, 전체 선택 범위 검색, 페이지 이동, 원문/추출 근거/완료 차단 사유와
`.rpt` 다운로드를 제공합니다. 실제 SSO/RBAC·운영 버전/PoR 저장과 구분합니다.
먼저 루트에서 `tools/build_public_preview.py --count 1000`을 실행하고 PostgreSQL 바이너리를 준비합니다.
정확한 명령·형식 출처·지원 범위·사내 AI 인계는 [공개 report 형식 안내](../../vwp_bridge/integration/PUBLIC_REPORT_FORMATS.md)를 읽습니다.
JSON 생성물은 Git에 포함하지 않으며 생성 후 `npm run build`하면 `dist/`에도 복사됩니다.

프로젝트·담당자 배정 흐름은 `/?demo=1&flow=access`에서 체험합니다. 상단의 가상 계정을
전환하면 관리자, 프로젝트 TOP, 블록 담당자, 미배정 사용자의 화면을 비교할 수 있습니다.
관리자의 **프로젝트 만들기**에서 기본 정보·TOP → 블록·담당자·검사 목록 → 확인의 3단계를
진행합니다. 등록한 검사는 모두 미수신 상태로 시작합니다. **담당자 설정**에서 배정을
추가·해제하고 프로젝트 관리 권한을 별도로 지정하면 다른 계정의 화면에도 즉시 반영됩니다.
TOP의 조회 범위와 관리 권한, 글로벌 프로젝트 생성 권한은 구분합니다. 변경 이력도 제공합니다.
이 데모는 브라우저 메모리에서만 동작하며 SSO·DB·실제 서버 권한 검증을 구현하지 않습니다.
새로고침하거나 **초기화**를 누르면 처음 상태로 돌아갑니다. `flow=access`만으로는 열리지 않습니다.

블록별 PoR·ECO 버전 조회는 `/?demo=1&flow=versions`에서 체험합니다.
**NET_VER·REVISION은 프로젝트 안의 각 블록에 속하며, 블록 담당자가 한 조합을 해당 블록의 PoR로 지정합니다.**
상단에는 블록별 담당자와 현재 PoR의 NET_VER·REVISION을 표시합니다. CPU·GPU·DDR의 버전 목록,
현재 PoR, ECO, 검사 결과는 각각 독립적입니다. 프로젝트 전체를 대표하는 공통 PoR 번호는 없습니다.
블록 → PRE/POST → NET_VER·REVISION → ECO → sanity 결과 순서로 조회합니다.

데모 사용자에서 **이영희 · Atlas TOP**은 모든 블록을 조회합니다. **김철수 · CPU 담당자**는
CPU를, **박민지 · GPU·DDR 담당자**는 GPU·DDR을 조회하고 각 담당 블록의 PoR을 지정합니다.
담당 블록에서 버전을 조회한 뒤 **CPU PoR로 지정** 같은 버튼으로 지정합니다.
단순한 버전·layout·ECO 조회는 PoR을 변경하지 않습니다. 지정은 해당 블록의 NET_VER·REVISION만
참조하며 다른 블록의 PoR, ECO, 기존 검사 결과를 변경하지 않습니다.
계정과 배정은 담당자 데모의 초기 예시를 재사용하며, 두 화면의 변경 상태를 공유하지는 않습니다.
이 권한 동작은 브라우저 데모이며 운영 SSO·서버 권한 검증은 아닙니다.

CPU NET_VER 예시는 `EVT0_ML3_DEV00 → EVT0_ML3_DEV01 → EVT0_ML4_DEV00`입니다.
GPU는 `EVT0_ML2_DEV01 → EVT0_ML3_DEV00`, DDR은 `EVT0_ML1_DEV00 → EVT0_ML2_DEV00`으로
블록별 진행 차이를 보여줍니다. CPU PRE revision `M4D0S1-hakhyun-Wsaif-v00-Cktran`의
POST revision은 `M4D0S1-hakhyun-Wsaif-v00-Cktran_beaifs-m5ps-BE`입니다.
전체 이름을 그대로 표시하며, PRE와 POST는 블록 내부에서 연결된 별도 세트로 보관합니다.
초기 PoR은 POST 조합이며 담당자는 PRE 또는 POST의 정확한 NET_VER·REVISION 조합을 지정할 수 있습니다.
이는 블록당 현재 PoR 하나를 두는 데모 동작이며, PRE·POST별 PoR 운영 정책의 최종 확정과 구분합니다.

POST 최초 ECO는 `chip_finish`이며 이후 예시는 `eco01 → eco02 → …`입니다.
같은 `eco01`이어도 프로젝트·블록·NET_VER·REVISION이 다르면 검사 결과와 실행 이력이 분리됩니다.
CPU의 `EVT0_ML4_DEV00` POST eco03은 결과 미수신 예시입니다.
운영 검사 결과의 원천은 VWP에서 전송한 데이터입니다. 대시보드는 수신 결과를 조회·검토하며,
검사 실행이나 PASS/FAIL을 생성·편집하지 않습니다. 이 데모는 미리 준비된 예시를 사용합니다.
PoR 지정과 검토는 브라우저 메모리에만 저장되며 새로고침·초기화 시 돌아갑니다.
실제 VWP·EDA·SSO·DB 호출이나 운영 데이터 변경은 없습니다.

GCA 예시는 `/?demo=1&dataset=gca` 또는 데모 배너의 **GCA 예시 보기**에서 엽니다.
Atlas/Boreal 두 가상 프로젝트, 프로젝트별 CPU/GPU/DDR 네 블록, 다섯 실행의
`CLK_0003`, `CAS_0003`, `CLK_0026`, `EXD_0012`, `B2T_CAS_0001` 사례를 제공합니다.
프로젝트·블록을 선택한 뒤 실행과 sanity item을 고르면 예시 보고서 전체·출처·`.rpt`
다운로드를 확인할 수 있습니다. 같은 이름의 블록도 프로젝트와 실행별 검토 이력을 분리합니다.
PASS와 report 미도착 상황을 포함하며 AI 분류는 실제 호출하지 않습니다.

자료는 [Synopsys GCA 백서](https://www.synopsys.com/content/dam/synopsys/implementation%26signoff/white-papers/GCA_wp.pdf)
(2010, pp. 2, 6–8)와 [PrimeTime GCA User Guide 공개 열람본](https://www.scribd.com/document/807828202/PrimeTime-GCA-User-Guide-2016)
(Synopsys, L-2016.06, Chapter 2 / Example 2-8 / Appendix A)을 참고했습니다.
문서의 검사 의미와 규칙 번호를 참고하되 객체·수치·판정·보고서 문구는 데모용으로 구성한 예시 데이터입니다.
vendor report 전체나 이미지를 복제하지 않았으며, native report 형식·현행 버전의 규칙 호환·
실제 파서·DB·AI 연동 검증 자료로 사용하지 않습니다. 규칙별 묶음은 동일 원인 확정이 아닙니다.
프로젝트·블록 선택은 이 데모의 예시 탐색 기능이며 운영 API의 범위 관리 구현을 뜻하지 않습니다.

화면에서 접수 목록과 실행을 선택하고, 전체 점검 대장·문제 그룹·원문 예시·생략 수를
확인할 수 있습니다. 사람의 판단은 현재 개정과 요청 UUID를 함께 제출합니다.
실패한 명령을 그대로 재시도하면 같은 UUID를 유지하고, 내용을 수정하면 새 UUID를
생성합니다. 개정 충돌 시 검토 창을 닫고 새로고침한 후 다시 검토해야 합니다.
FAIL을 PASS로 바꾸는 입력과 분석 미완료 항목의 검토는 비활성화하며 서버에서도 검증합니다.

추가 근거는 알려진 기록 ID를 직접 입력할 수 있으며 PASS 항목에서도 요청할 수 있습니다.
VWP 요청 처리 상태와 OA 응답 수신 상태를 따로 보여줍니다. OA에서 응답을 검증하여
`RECEIVED`로 처리한 뒤에만 근거 본문을 열 수 있습니다. 근거 수신은 사람의 승인과 별개입니다.
이력은 API가 반환하는 최근 50개 범위와 전체 개수를 표시하며 전체 기록은 서버에 보존됩니다.
검색과 필터는 현재 점검 대장 페이지에만 적용합니다.
위의 1,000개 report 미리보기에서는 현재 프로젝트/블록의 전체 범위에 먼저 검색·필터를 적용하고 페이지를 나눕니다.

브라우저 검증:

```sh
npx playwright install --with-deps chromium
SANITY_DASHBOARD_TEST_PORT=5188 npm run test:e2e
```

Playwright는 실제 Chromium에서 명시적 데모, 로그인과 토큰 비저장, API 실패,
UUID 재시도·개정 충돌, 읽기 전용, 판단 기록, 근거 요청·응답, 보고서 다운로드,
390px 모바일 화면을 확인합니다. 데모 및 API 모킹 기반 UI 테스트이며 실제 DB·API 통합
검증은 상위 프로젝트 테스트와 별도로 수행합니다. 화면 캡처는 `artifacts/`,
결과 보고서는 `playwright-report/`에 생성됩니다.
1,000개 preview의 테스트는 미리 생성한 합성 스냅샷도 필요합니다. 테스트 포트를 지정하면 해당 디렉터리의 개발 서버를
새로 시작하고 종료하며, 다른 worktree의 기존 5173 서버와 섞이지 않습니다.

그룹별 분류 근거 V2에서는 선택 그룹의 로그 옆에서 AI/참고 엔진 제안과 대표 원본을 확인하고, `근거 수정`으로 분류 기준·대표 로그·수정 사유를 저장합니다.
이동/병합/분리로 바뀐 그룹은 근거 재검토가 필요합니다. `분류 확정 · 판정 시작`은 현재 개정의 유효한 미확인 초안을 일괄 채택하며 2단계로 진행합니다. 전체 메모는 선택 입력입니다.
구형 근거 미작성 자료는 이력을 유지하며 새 확정 전에 보완합니다. TOP은 조회만 가능합니다.
브라우저 회귀는 별도 합성 QA 서버에서 `npx playwright test --config playwright.rationale.config.ts`를 사용합니다. 외부 모델은 호출하지 않습니다.

## Shadcn Studio 검토 시안

`/studio.html`에서 승인한 Shadcn Studio 디자인을 별도로 확인합니다. `npm run dev`와
`npm run build` 모두 이 진입점을 제공하며, 빌드 결과는 기존 `dist/`에 포함됩니다.
예: `http://127.0.0.1:5173/studio.html`, 어두운 화면은 `/studio.html?theme=dark`입니다.

그룹 목록은 의미를 추측한 아이콘 대신 **순번·이름·로그 건수·검토 상태**를 표시합니다.
순번은 현재 합성 보고서의 원래 그룹 순서이며 검색과 상태 필터로 다시 매기지 않습니다.
고정 분류 사전이나 그룹의 의미를 나타내는 ID가 아닙니다.

프로젝트 맥락 / 그룹 / 로그·원문 / 판정·근거를 나란히 배치하고 모바일에서는 세로로
연결합니다. 검색·페이지·체크박스 선택·탭·검토 이력 시트·밝은/어두운 화면을 체험할 수 있습니다.
원본 도구 결과, 합성 AI 제안, 사람의 판정은 구분하며 보류는 완료로 집계하지 않습니다.
합성 5개 그룹·126개 로그만 사용하고 확정 내용은 탭 메모리에 저장되어 새로고침하면 초기화됩니다.
실제 API·SSO·DB·모델 호출은 없습니다. 운영 화면의 분류 편집·권한·개정·AI 연동을
대체하지 않는 독립 시안입니다. 시안의 Studio UI 컴포넌트는 실제 운영 화면에서도 사용하며,
시안 전용 합성 데이터·독립 다크 테마·레이아웃 CSS는 `studio.html` 진입점에 남겨 둡니다.
실제 화면은 `studio-system.css`의 공통 토큰과 `live-workbench.css`의 검토 레이아웃을 사용합니다.
실제 SSO 화면은 `/`와 `/api/*`, 독립 합성 앱은 `/workspace`와 `/workspace/api/*`를 사용한다는 기존 계약을 유지합니다.
UI 변경은 회사 AI 접속, 100,000건의 모델 처리 완료나 새로운 권한 승인을 의미하지 않습니다.
