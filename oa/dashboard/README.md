# Design Atlas 대시보드

React·TypeScript·Vite·Tailwind CSS와 Radix 기반 Shadcn Studio 구성 요소를 사용하는 한국어 검토
화면입니다. 외부 폰트·CDN·분석 서비스 호출 없이 로컬 Pretendard·Geist Mono와 시스템 폰트를 사용합니다.
서버 API와 같은 출처에서 제공하며, 접근 토큰은 탭 메모리에만 보관합니다.

UI 문구는 기능명·입력 조건·상태·오류·권한 안내를 중심으로 표시한다. 홈·로그인·프로젝트 비교·권한 데모의 슬로건과 중복 소개는 제거한다. 실제 데이터와 합성 데모의 구분, 저장·권한·비교 조건 안내는 유지한다.

기본 `/`는 공통 홈이다. 프로젝트를 한 번 선택하고 하나의 사이드바에서 로그 검토·수신 대장·**프로젝트 비교**를 연다. `/api/atlas/*`의 실제 공통 카탈로그와 수치 범위 준비를 사용하며 별도 Area 프로젝트 등록은 없다. URL 범위는 업무 이동·뒤로 가기·새로고침에 보존한다. 현재 접속·실행·검증은 [제품 인계](../../HANDOFF.md)를 따른다.
관리자가 공통 홈에서 프로젝트를 등록할 때 이름·설명만, 프로젝트를 고른 뒤 블록을 등록할 때 이름만 입력합니다. 등록 API가 반환한 canonical project/block ID가 카탈로그와 이후 버전·수집 범위에 사용됩니다. 같은 정확한 이름을 다시 등록해도 새 항목을 만들지 않으며, 같은 블록 이름도 프로젝트별로 구분됩니다. 클라이언트·CLI는 이름으로 ID를 생성하지 않습니다. 버전 ID identity와 Area UUID binding 및 업로드 metadata 계약은 별도이며 기존 canonical ID/선택값을 그대로 사용합니다.

화면에는 프로젝트·블록 이름을 표시하고 내부 ID는 표시하지 않습니다. 이름을 확인할 수 없는 항목도 ID로 대체하지 않습니다. API·DB·URL 선택값과 PC 업로드 메타데이터에는 정확한 연결용 ID를 유지합니다. 업로드 JSON은 복사하며 클립보드를 사용할 수 없으면 파일로 내려받습니다.

## 화면 기준 (1920×1080 데스크톱)

대부분의 사용자가 1920×1080 데스크톱을 쓰므로 이 해상도를 기준으로 글자 크기·밀도·배치를 맞춘다. 모바일은 대상이 아니다.

- **글자 크기 토큰**: 15px 미만의 글자 크기는 `theme.css`의 `--text-micro`(11px)·`--text-caption`(12px)·`--text-data`(13px)·`--text-body`(14px)·`--text-lead`(15px)만 사용한다. 화면별 CSS에 15px 미만 px 값을 직접 쓰지 않는다. 전체 크기를 조정할 때는 토큰 값만 바꾼다. 프로젝트 비교 화면(`src/areaPower/`)의 전용 스타일은 아직 토큰으로 옮기지 않았다.
- **줄바꿈**: 본문은 `word-break: keep-all`로 한국어를 어절 단위로 줄바꿈하고, 긴 ID·경로는 `overflow-wrap: break-word`로 넘치지 않게 한다.
- **페이지 틀**: 홈·로그 검토·수신 로그 대장·계정·관리 화면은 같은 왼쪽 여백(30px)에서 시작하고 페이지 제목은 24px 한 줄(제목 옆 설명)로 통일한다. 사이드바 상표와 첫 메뉴 사이에는 간격을 둔다.
- **홈**: 위쪽 ‘선택한 범위’ 줄에서 현재 프로젝트 › 블록 › 버전과 **로그 검토 열기 / 프로젝트 비교 열기**를 바로 사용한다. 아래의 프로젝트·블록·버전 세 열에서 항목 전체를 눌러 선택하며, 선택은 상단 공통 범위와 같은 값이다. 등록·선언 버튼은 각 열 머리에 둔다.
- **버전·검사 대장**: 탭·제목·PoR/조회 버전·집계·Sanity 항목·안내 줄의 세로 여백을 줄여 1080px 높이에서 보고서 표가 화면 중간 위에서 시작한다. 행의 **검토 시작**은 테두리형 강조 버튼이고 동작 열은 표 오른쪽 끝에 붙인다.
- **수신 로그 대장**: **수신 내용 보기**를 누르면 너비 1500px 이상에서는 목록 오른쪽에 고정된 상세 패널이 열리고, 더 좁으면 목록 아래에 열린 뒤 그 위치로 스크롤한다.
- **로그 검토 상세**: 분류 초안을 만들기 전에도 작업 영역이 페이지 전체 너비를 쓴다. 너비 1700px 이상에서는 맥락·그룹·판정 열을 넓히고 로그 표의 모드 값을 말줄임 없이 표시한다.
- 보고서 창의 탭은 밑줄형이며 선택한 탭만 굵게 표시한다.

사이드바의 **Area/Power**에는 `/?page=area-power`의 **프로젝트 비교** 하나만 둔다. 기존 Area `view=` 딥링크도 이 경로로 정리한다. AI·작업·알림·target·변경 설명을 별도 주 탐색이나 비교의 선행 입력으로 요구하지 않는다. 로그 메뉴·홈·계정·관리와 기존 인증/권한 표시는 유지한다.

상단 공통 범위는 **접기 / 펼치기**를 지원한다. 접으면 프로젝트·블록·NET_VER·REVISION 개요만 표시하고 선택값은 바뀌지 않는다. 접힘 상태는 같은 탭의 메뉴 이동 동안 유지한다. 프로젝트 비교와 CLI 메타데이터의 선택은 이 범위와 독립적이다.

버전은 **NET_VER → REVISION**으로 나누어 선택한다. NET_VER는 각 선택기의 블록에서 중복 없이 표시하며 REVISION은 선택한 NET_VER에 속한 유효한 항목만 표시한다. PRE/POST를 함께 표시하고 실제 선택값은 기존 version UUID를 사용하므로 API·DB·URL 계약은 바뀌지 않는다. 프로젝트·블록 변경은 같은 선택기의 하위 선택을 초기화한다. REVISION 선택 전 NET_VER와 접힘 상태는 탭 안의 임시 UI 상태여서 새로고침하면 초기화된다.

데스크톱(너비 1101px 이상)의 공통 상단은 헤더와 범위 선택 줄의 세로 여백을 줄이고, 범위 이름·선택값을 나란히 표시하며 선택기·범위 버튼은 32px 기준으로 맞춘다. 기본 펼침과 접기 상태·선택 동작은 그대로다. 통합 로그 화면의 ECO 선택·현재 PoR/조회 버전 카드·PASS/FAIL/보류 집계 줄도 간결하게 표시하되 버전·담당자·지정 시각·모든 상태 이름과 건수는 유지한다. 긴 내용은 기존 줄바꿈을 허용하며 선택기의 포커스·비활성 표현은 공통 스타일을 따른다.

로그 검토 상세의 데스크톱 작업 영역은 공통 헤더·범위 선택 영역을 제외한 실제 viewport 높이를 채운다. 작은 화면은 기존 흐름을 유지하고, 최소 작업 높이가 필요한 경우에는 내용을 잘라내지 않고 스크롤한다. 통합 shell의 `data-page`로 활성 업무에만 적용하므로 보관 중인 로그 화면이 다른 메뉴의 높이를 제한하지 않는다.

메뉴 복귀나 URL 범위 변경 시에는 해당 경로가 로컬 선택 상태에 적용된 뒤에만 URL을 다시 기록한다. 이전 선택값을 새 경로에 재출력하는 반복 업데이트를 막으며 React Activity 보관과 기존 세션·권한 검사는 유지한다.

메뉴를 빠르게 바꿔 취소된 이전 이동은 오류로 표시하지 않는다. 업무 전환마다 서버 세션을 다시 확인하고 로그 화면에는 같은 진입에서 확인한 최신 세션을 전달한다. 권한 준비 전에는 공통 업무 카탈로그를 요청하지 않는다. 카탈로그의 `area_status=unavailable`이면 Area 목록 조회를 시작하지 않고 서비스 준비 안내를 표시한다. 설치·연결 복구 후 새로고침으로 카탈로그부터 다시 확인한다. 실제 서버 오류는 숨기거나 자동 재시도하지 않는다.

로그의 현황·버전·검사 대장·이력 조회는 실패 시 로딩을 끝내고 각 조회의 오류를 표시한다. 메뉴 복귀나 새로고침 후 성공한 조회는 자신의 이전 오류만 해제하며 다른 조회·저장 오류는 유지한다. 화면을 떠나면 진행 중인 현황 조회도 취소한다. 응답 본문을 읽는 중의 취소는 그대로 전파하고, 잘못된 JSON을 정상 조회 결과로 사용하지 않는다. 서버의 5xx 진단에는 공개 오류 코드·예외 타입·SQLSTATE·코드 위치만 남기며 SQL·접속 정보·요청 본문은 기록하지 않는다.

## 통합 합성 데모

**[데모 열기](http://127.0.0.1:8080/login?to=%2Fproxy%2F8000%2F%3Fdemo%3D1)** — 기존 데모 창은 새로고침한다. `?demo=1`은 공통 홈·사이드바·프로젝트/블록/버전과 로그·Area/Power 화면을 실제 앱과 같은 구성 요소로 제공한다. 상단 합성 계정 선택은 같은 메모리 카탈로그와 프로젝트 배정에 적용된다.

프로젝트의 단방향 기준 저장/해제·동시 수정 충돌, 명시적 양쪽 실행, 같은 화면의 다중 node/subtree 대응, 펼칠 수 있는 hierarchy Area/Power 표와 고정 비교 이력을 현재 탭에서 조작한다. 합성 계산도 정확한 BigInt 유리수를 쓰며 유한 십진수는 자르지 않는다. 반복 소수의 표시만 30자리에서 반올림하고 정확한 분자/분모는 보존한다. 메모리 작업자는 queued→running→completed로 실제 합성 수치를 계산하며 실제 DB 큐가 아니다. AI는 호출하지 않고 needs_review로 남긴다. 실제 DB·SSO·VWP·메일을 호출하거나 실패한 운영 요청을 데모로 대체하지 않는다.

등록/선언만으로 보고서·수신 ECO·측정 파일을 만들지 않는다. 메타데이터 JSON은 합성 UUID 예시이므로 실제 VWP로 보내지 않는다. 새로고침·데모 초기화는 편집/계정/숫자 상태를 초기화하고 이전 페이지의 snapshot UUID를 제거한다. 종료는 실제 앱으로 문서 이동하며 실제 SSO 로그아웃을 호출하지 않는다. 별도 `flow=access|versions`·`dataset=reports` 등의 명시적 미리보기는 유지한다.

## 프로젝트 비교

- 기준이 저장되어 있으면 간결한 **A→B** 개요와 변경 버튼을 표시한다. 설정은 현재 프로젝트 하나의 `baseline_project_id`와 `row_version` CAS로 기존 project payload에 저장한다. 반대 방향이나 다른 프로젝트의 기준은 바꾸지 않고 추가 DDL도 없다. 프로젝트만 연결하면 CSV·블록·버전 없이 먼저 기준을 지정할 수 있다.
- 비교할 현재 프로젝트는 화면 안에서 선택한다. 양쪽 Block → NET_VER → REVISION → Corner → 실행 파일도 상단 범위와 독립적이다. NET_VER 변경은 같은 쪽 REVISION과 하위 선택을 해제하며, 현재 쪽 변경으로 기준 쪽 실행을 바꾸지 않는다. 기준 프로젝트는 현재 프로젝트에 저장된 지정을 사용하고 변경 버튼으로 명시적으로 교체·저장한다. 양쪽 실행은 최신 시각·이름으로 짝을 만들지 않는다. 선택한 native 버전의 정확한 Area binding이 없으면 다른 블록/버전 파일을 표시하지 않는다.
- Corner의 전압·온도 키는 부동소수점 변환 없이 십진수 자릿수·지수를 정규화한다. `0.70`과 `0.7`, `25.0`과 `25`는 같은 조건으로 묶고 서로 다른 정밀한 값은 구분한다. 선택기에는 원본의 읽기 쉬운 PVT 표기와 단위를 유지한다.
- 주 화면의 표 하나에서 hierarchy instance별 기준/현재 Area·Power(mW), Δ·%와 각각의 비교 가능성/사유를 읽는다. 처음에는 루트만 표시하고 가지 단위로 펼친다. 부모 수치는 자식을 포함하므로 행을 다시 합산하지 않는다. 경로 인덱스와 표시할 가지를 사용하며 모든 행의 쌍별 탐색/중복 미리보기를 만들지 않는다.
- 기준 실행이나 경로 대응이 없어도 현재 관측값은 보존한다. 상대 값·Δ·%는 unavailable이며 0으로 보완하지 않는다. 기준이 0인 상대 변화율도 계산하지 않는다. Corner가 다른 Power는 조건 차이와 contextual 상태를 유지하고 Area의 상태와 혼동하지 않는다.
- 표의 %만 정확한 십진수/BigInt 반올림으로 소수점 두 자리까지 간결하게 표시한다. 전체 서버 원문 수치는 해당 셀의 title·접근성 설명에 남기며 저장값·산술·Area/Power 절대값은 바꾸지 않는다. 정상/이상 판정이 아닌 수치 비교라는 안내는 표 위에 한 번 표시하고 각 지표의 실제 비교 불가/조건 차이 사유는 유지한다.
- **구조 대응 설정**은 양쪽 실행 파일을 선택하면 비교 실행 전에 사용할 수 있다. 기준/현재 경로는 문자열을 입력한 뒤 일치하는 결과에서 선택하거나 전체 경로를 붙여넣는다. 빈 검색창에는 전체 목록을 펼치지 않으며 검색 결과는 페이지로 나눈다. 선택한 원본 경로의 대소문자·구분자를 유지한다. 조회 중·조회 실패·빈 목록·검색 결과 없음을 양쪽에서 구분한다. root↔root subtree 또는 개별 node 대응을 여러 개 추가해 같은 mapping revision으로 저장한다. Subtree는 상대 경로가 같은 하위 노드까지 연결하며 이름이 달라진 자식에는 별도 규칙을 넣는다. 규칙이 없는 다른 프로젝트 경로는 양쪽 design 루트 아래 상대 경로가 같을 때 자동 대응하며 명시 규칙이 우선한다(새 비교부터 적용). 비교 결과는 Hierarchy Browser 트리로 표시한다. 단일 루트의 1단계를 펼쳐 시작하고 펼칠 때 해당 노드의 직계 자식만 조회(500개 단위 더 보기)한다. Instance 열은 instance 이름·기준 이름 차이·하위 개수, Area/Power는 기준·현재·Δ·Δ%를 보이며 열 머리로 형제 행을 정렬한다. ↑↓/→/←/Enter 키 이동, 변화·미대응만 보기, 선택 행의 전체 경로·수치 상세를 제공한다. 검색 결과는 전체 경로의 평면 목록이다. 기본 보기는 Meld식 좌우 비교로, 기준(왼쪽)·변화율(가운데)·현재(오른쪽)가 한 행을 공유해 펼치기/접기가 양쪽에 동시에 적용되고 대응 instance가 같은 줄에 정렬된다. 한쪽에만 있는 instance는 빗금 빈칸, 추가·삭제·변경(이름 차이 또는 Δ≠0/비교 불가)은 색으로 구분하며 이전/다음 차이(Alt+↑↓)로 이동한다. 비교 실행 전 미리보기는 루트 기준 상대 경로로 표시만 정렬하고 Δ는 계산하지 않는다. 단일 표 보기로 전환할 수 있다. 형제 행의 기본 정렬은 Area 큰 순(현재, 없으면 기준)이며 Instance 머리는 이름순이다. 프로젝트 선택과 기준은 한 줄로 표시하고, 비교를 실행하거나 이력에서 열면 실행 선택을 한 줄 요약으로 접어 표가 화면 대부분을 쓰게 한다. ‘크게 보기’는 표만 화면 전체로 띄우고 Esc로 돌아간다. 기본 열은 Area·Power·Vth(SLVT/LVT/RVT/HVT %)이고 ‘열 선택’에서 Area·Vth(LLP 포함)·Power 구성요소·Drive·Cells를 최대 14개 고른다(비율은 Δ%p). ‘Area ≥’ 임계값(기본 50, 비우면 전체)은 현재·기준 중 큰 area가 미만인 하위 instance를 숨기고 숨긴 수를 표시하며 루트는 항상 보인다. 열과 임계값은 이 브라우저에만 저장한다. 비교 대상은 ‘기준 프로젝트와 비교’ 또는 ‘같은 프로젝트의 이전 버전과 비교’를 고른다(이전 버전은 같은 Block의 명시적 계보). ‘AI 분석용 메모 · 주요 instance’ 패널에서 NET_VER 업데이트 메모·프로젝트 변경 메모·주요 instance 경로를 저장하고, 기준 설정에서 프로젝트 공정을 등록한다. 비교를 연 뒤 ‘AI 분석’에서 기준 숫자를 정해 미리보기로 대상 수를 확인하고 실행한다. 결과는 이상·확인 필요·주요 instance·설명됨으로 나뉘며 항목을 누르면 표에서 그 instance까지 펼쳐 선택하고 행에 판정 표시가 붙는다. ‘메일 보내기’는 ‘제외’한 항목을 뺀 요약 메일 한 통을 요청한다. 합성 데모는 AI와 메일을 호출하지 않고 모든 판정을 확인 필요로 남긴다. raw UUID/JSON·target·정책·AI 입력은 비교 필수가 아니다.
- `Export template`으로 UTF-8 CSV를 내려받아 `baseline_path,current_path,scope` 열을 작성한 뒤 `Import mapping CSV`로 불러온다. 한 행은 일대일 대응이며 scope는 `node` 또는 `subtree`다. 인용된 쉼표·따옴표·줄바꿈과 UTF-8 BOM을 지원한다. 모든 행의 경로와 중복을 검사한 뒤 작성 중 목록을 통째로 교체하며, 오류가 있으면 기존 목록을 유지한다. 가져온 목록을 확인하고 대응 저장 버튼으로 서버에 저장한다. 분할·병합을 같은 경로의 일대일 중복으로 입력하지 않는다.
- 기준 변경 후에도 비교는 당시 upload/snapshot·mapping revision을 사용한다. 기존 비교는 저장된 scalar 값과 기본 고정 upload pair의 Power를 표시한다. 새 참조 비교는 조회 준비 완료와 전체 지표 분석을 구분하며 현재 경로 페이지의 total area·total power를 조회할 때 계산한다. 한 번에 200그룹을 표시하고 경로 검색·이전/다음으로 전체에 접근한다. 새 결과에서 모든 원본 hierarchy를 다시 로드하거나 fallback 행을 만들지 않는다. 실행 중 queued/pending/running은 `view=summary`로 작은 상태/coverage만 읽는다. 완료·실패 결과도 갱신 버튼으로 다시 읽는다. 데이터 새로고침은 동일 기준의 선택/작성 중 대응을 지우지 않는다.
- 업로드 이력·원본 gzip·PC CLI 메타데이터와 저장된 비교 이력은 접힌 보조 영역이다. CLI 메타데이터 창에서도 프로젝트·블록·버전·snapshot을 독립적으로 선택하며 정확한 Area UUID를 사용한다. 기존 업로드 계약은 유지한다. 활성 SSO 사용자는 현재·기준 결과와 원본을 배정 없이 조회한다. 기준 교체/해제와 새 분석·매핑 변경은 현재 프로젝트 수정 권한이 필요하다.



## 기존 로그 화면과 명시적 합성 미리보기의 세부 동작

검토 상세에서도 사이드바를 자동으로 숨기지 않습니다. 통합 화면은 공통 탐색 메뉴 하나만 유지하고, 기존 독립 Workspace도 검토 진입·종료 시 접기·펼치기와 저장된 폭을 유지합니다.

데스크톱에서는 사이드바 오른쪽 경계를 드래그해 폭을 조절합니다. 사용자·관리자 화면이 같은 폭을 사용하고,
브라우저에 저장한 폭은 새로고침이나 접기·펼치기 후에도 유지됩니다. 경계를 두 번 클릭하면 기본 폭으로 돌아갑니다.
경계에 키보드 초점을 두면 좌우 방향키(8px), Shift+방향키(24px), Home/End로도 조절할 수 있으며,
드래그 중 Esc를 누르면 변경을 취소합니다. 접기·펼치기는 본문과 함께 220ms 동안 전환하고,
동작 줄이기 설정에서는 즉시 전환합니다. 화면 크기에 맞춰 최소 216px·최대 360px 안에서 조절합니다.

프로젝트·담당자·블록별 버전·PoR의 업무 규칙과 운영 구현안은
[요구사항 15절](../../requirement.md#dashboard-domain-spec)을 따릅니다. 아래는 현재 데모의 사용법과 구현 범위입니다.

운영 SSO의 AI 작업 화면은 **`/?page=workbench`**, 업무 API는 **`/api/workbench/*`**입니다.
**`/workspace`**와 `/workspace/api/*`는 별도로 실행하는 독립 합성 앱이며 운영에 자동 마운트하지 않습니다.
활성 SSO 사용자는 배정 없이 모든 등록 프로젝트/블록/버전/검사/PoR을 조회합니다. 변경·AI 실행은 해당 프로젝트의 수정 권한을 따릅니다.

운영 SSO에서 **서버가 확인한 관리자 계정에만** 사이드바의 **사용자 / 관리자** 모드 전환을 표시합니다.
선택 배경은 좌우로 이동하며 사용자 모드에서는 업무·권한 신청 메뉴, 관리자 모드에서는 관리 메뉴를 보여줍니다.

입력값을 같은 탭에서 유지합니다. 숨긴 화면의 effect·조회·모바일 포커스 처리는 중단하고 복귀할 때 최신 자료를 조회합니다.
뒤로/앞으로 가기도 지원하며, 전환 전에 현재 SSO 세션을 다시 확인합니다. 계정·권한 변경이나 인증 만료가 확인되면
보관한 화면을 폐기하고 최신 조회·수정 가능 상태를 읽거나 로그인 화면을 엽니다. 로그아웃도 보관한 화면을 제거합니다.

로그 표는 기본 34px(휴대폰 40px) 높이의 한 줄 행으로 대상·요약을 표시합니다. 긴 값은 말줄임하며 전체 원문·로그 ID·파싱 필드는 선택 원문 패널에서 확인합니다.
데스크톱에서는 제목과 단계·동작 버튼을 한 줄에 배치하고, 원문 패널은 기본 124px로 제한해 로그 목록이 남은 화면 높이를 사용합니다. 목록의 열 제목은 내부 스크롤 중에도 고정되며, 긴 원문과 파싱 필드는 원문 패널 안에서 스크롤합니다.
최초 조회에는 스피너와 뼈대 행을 표시합니다. 검색·페이지 변경 중에는 기존 목록과 원문을 흐리게 표시하고 선택·이동·복사를 잠시 막습니다. 조회 상태는 `aria-busy`와 상태 메시지로도 전달합니다.
모바일에서는 영역을 세로로 연결하고 원본 도구 결과·AI 제안·사용자 판정을 모두 표시합니다. 전문 용어를 유지하며 긴 근거·대표 로그·출처·이력·상세 집계·재사용 설정은 펼쳐서 조회합니다.
**분류 확정 · 판정 시작**으로 전체 그룹의 유효한 근거 초안을 일괄 채택하고 분류를 확정합니다. 전체 메모는 선택 사항입니다.
판정은 **PASS / FAIL / 보류**와 **판정 근거**를 기록합니다. 보류 그룹이 남으면 완료로 표시하지 않습니다.
선택형 **이번 판정을 규칙 예외로 기록**을 켜면 예외 대상 규칙·예외 사유·성립 조건을 함께 저장합니다. 예외도 다음 AI의 참고 사례가 되며, 다음 report에서는 조건을 다시 검토합니다. 예외 체크는 자동 PASS나 원본/분류 미완료의 면제가 아닙니다.
**AI 참고 허용 체크는 없습니다.** 모든 프로젝트·블록·revision·ECO의 확정 지식이 관련 참고 후보가 되며 AI가 출처와 조건 차이를 비교합니다. 원문 조회 권한은 그대로 유지하고 참고 사례에는 과거 원문 대신 사람이 확정한 그룹·판정·근거·예외와 출처를 표시합니다. 기존 참고 엔진의 조건 적용 승인은 일반 판정 편집에서 보존하고 예외·보류로 변경해 저장할 때 해제해 이전 이력에 남깁니다.
일반 버튼은 마우스를 올리면 색·테두리·그림자가 부드럽게 바뀌며 동작 버튼은 1px 떠오릅니다. 체크박스·단계·탭·로그 이동 손잡이와 비활성 버튼은 위치를 유지합니다. 터치 환경과 모션 감소 설정에서는 이동 효과를 적용하지 않습니다.
UI 동작 검증은 사내 데스크톱 전용으로 수행합니다. 모바일 viewport·기기 에뮬레이션·모바일 브라우저 케이스는 실행하지 않으며, 모바일 케이스를 포함한 기존 브라우저 모음을 통째로 실행하지 않습니다. 로그 검토의 지정 해상도는 1920×1080과 5120×2160입니다. 실제 저장·사람 확정 등의 검증이 필요한 경우에도 데스크톱 범위로 한정하며 외부 모델은 호출하지 않습니다.

빌드 기준은 **Node 20.18.0**이다. Vite 6.4.4와 React 플러그인 4.7.0을 고정하고,
lockfile로 하위 의존성도 고정한다. Node 버전 관리 도구를 쓰면 이 디렉터리의 `.nvmrc`를 적용한다.
회사 Docker 구성은 [Docker 실행 안내](../docker/README.md)를 따른다.

```sh
cd oa/dashboard
npm ci --engine-strict
npm run build
```

프런트엔드에 서버 토큰, DB 비밀번호나 연결 문자열을 넣지 않습니다. 브라우저 저장소나
URL에 인증 토큰을 기록하지 않으며 새로고침 후 다시 로그인해야 합니다.

`npm ci`와 빌드를 실행할 수 있는 오프라인 환경을 구성해야 합니다.

데모에서는 API·SSO·DB·AI를 호출하지 않으며 변경 내용을 현재 탭 메모리에만 저장합니다.
API 장애·인증 실패 시 오류를 표시하고 자동으로 데모로 바꾸지 않습니다.

기본 계정은 `user04`이며 상단 **데모 계정**에서 담당자와 TOP의 조회 범위를 비교합니다.

**그룹 초안 만들기 → 로그 이동·분리·병합 / 근거 검토 → 분류 확정 · 판정 시작 → 사용자 판정**을 체험합니다.
블록별 PoR 지정·변경 이력, 항목별 검색·필터·페이지, 합성 원문 다운로드도 제공합니다.
같은 탭에서 계정을 전환하면 데모 변경을 공유하며, 새로고침하면 계정과 변경이 모두 초기화됩니다.
각 블록의 최신 `NET_002` POST / `chip_finish`에는 합성 검사 38개(GCA 28·VC LP 5·SpyGlass 5)가 있습니다.
이전 `NET_001` POST에는 14개가 있으며 PRE와 `eco01`은 미수신 예시입니다. 부분 해석·미수신 보고서를 완료로 표시하지 않습니다.
합성 로그의 필드 값으로 만드는 데모 초안은 실제 파서·참고 사례 엔진·AI의 동작 검증 자료가 아닙니다.

도구 결과 PASS인 합성 로그 27건을 3개 그룹으로 미리 분류 확정했으며, **그룹별 판정**에서 PASS 제안과 직접 근거를 확인할 수 있습니다.
실제 모델 호출 없이 준비한 예시이며 사용자 판정은 미확정입니다. **제안 적용 → 판정 저장**으로 사람의 확정을 체험합니다.

SANITY_DASHBOARD_TEST_PORT=5180 npm run test:e2e

기존 번들 검토 대장은 **`/?demo=1&flow=legacy`**에서 유지합니다. 상단 **다른 예시**에서
이전 검토 대장·GCA 보고서·프로젝트 담당자·버전 데모를 열 수 있습니다.

1,000개 report parser 미리보기는 `/?demo=1&dataset=reports`에서 엽니다. 이용자 10명, 프로젝트 3개,
각 프로젝트의 CPU/GPU/DDR 3개 블록을 가정한 합성 데이터입니다. GCA·VC LP·SpyGlass의 초기 파서를 통해
실제 독립 PostgreSQL에 넣고 OA 수신을 확인한 **읽기 전용 스냅샷**을 표시합니다. DB와 AI를 실시간 호출하지 않습니다.
가상 계정의 담당 범위 전환, 도구·결과 필터, 전체 선택 범위 검색, 페이지 이동, 원문/추출 근거/완료 차단 사유와
`.rpt` 다운로드를 제공합니다. 실제 SSO/RBAC·운영 버전/PoR 저장과 구분합니다.
먼저 루트에서 `tools/build_public_preview.py --count 1000`을 실행하고 PostgreSQL 바이너리를 준비합니다.
정확한 명령·형식 출처·지원 범위·사내 AI 인계는 [공개 report 형식 안내](../../vwp_bridge/integration/PUBLIC_REPORT_FORMATS.md)를 읽습니다.
JSON 생성물은 Git에 포함하지 않으며 생성 후 `npm run build`하면 `dist/`에도 복사됩니다.

프로젝트·담당자 배정 흐름은 `/?demo=1&flow=access`에서 체험합니다. 상단의 가상 계정을
전환하면 관리자, 프로젝트 TOP, 블록 담당자, 미배정 사용자의 화면을 비교할 수 있습니다.
관리자의 **프로젝트 만들기**에서 기본 정보·TOP → 블록·담당자·검사 목록 → 확인의 3단계를
진행합니다. 등록한 검사는 모두 미수신 상태로 시작합니다. **담당자 설정**에서 배정을
추가·해제하고 프로젝트 관리 권한을 별도로 지정하면 다른 계정의 화면에도 즉시 반영됩니다.
TOP의 조회 범위와 관리 권한, 글로벌 프로젝트 생성 권한은 구분합니다. 변경 이력도 제공합니다.
이 데모는 브라우저 메모리에서만 동작하며 SSO·DB·실제 서버 권한 검증을 구현하지 않습니다.
새로고침하거나 **초기화**를 누르면 처음 상태로 돌아갑니다. `flow=access`만으로는 열리지 않습니다.

블록별 PoR·ECO 버전 조회는 `/?demo=1&flow=versions`에서 체험합니다.
**NET_VER·REVISION은 프로젝트 안의 각 블록에 속하며, 블록 담당자가 한 조합을 해당 블록의 PoR로 지정합니다.**
상단에는 블록별 담당자와 현재 PoR의 NET_VER·REVISION을 표시합니다. CPU·GPU·DDR의 버전 목록,
현재 PoR, ECO, 검사 결과는 각각 독립적입니다. 프로젝트 전체를 대표하는 공통 PoR 번호는 없습니다.
블록 → PRE/POST → NET_VER·REVISION → ECO → sanity 결과 순서로 조회합니다.

데모 사용자에서 **이영희 · Atlas TOP**은 모든 블록을 조회합니다. **김철수 · CPU 담당자**는
CPU를, **박민지 · GPU·DDR 담당자**는 GPU·DDR을 조회하고 각 담당 블록의 PoR을 지정합니다.
담당 블록에서 버전을 조회한 뒤 **CPU PoR로 지정** 같은 버튼으로 지정합니다.
단순한 버전·layout·ECO 조회는 PoR을 변경하지 않습니다. 지정은 해당 블록의 NET_VER·REVISION만
참조하며 다른 블록의 PoR, ECO, 기존 검사 결과를 변경하지 않습니다.
계정과 배정은 담당자 데모의 초기 예시를 재사용하며, 두 화면의 변경 상태를 공유하지는 않습니다.
이 권한 동작은 브라우저 데모이며 운영 SSO·서버 권한 검증은 아닙니다.

CPU NET_VER 예시는 `EVT0_ML3_DEV00 → EVT0_ML3_DEV01 → EVT0_ML4_DEV00`입니다.
GPU는 `EVT0_ML2_DEV01 → EVT0_ML3_DEV00`, DDR은 `EVT0_ML1_DEV00 → EVT0_ML2_DEV00`으로
블록별 진행 차이를 보여줍니다. CPU PRE revision `M4D0S1-hakhyun-Wsaif-v00-Cktran`의
POST revision은 `M4D0S1-hakhyun-Wsaif-v00-Cktran_beaifs-m5ps-BE`입니다.
전체 이름을 그대로 표시하며, PRE와 POST는 블록 내부에서 연결된 별도 세트로 보관합니다.
초기 PoR은 POST 조합이며 담당자는 PRE 또는 POST의 정확한 NET_VER·REVISION 조합을 지정할 수 있습니다.
이는 블록당 현재 PoR 하나를 두는 데모 동작이며, PRE·POST별 PoR 운영 정책의 최종 확정과 구분합니다.

POST 최초 ECO는 `chip_finish`이며 이후 예시는 `eco01 → eco02 → …`입니다.
같은 `eco01`이어도 프로젝트·블록·NET_VER·REVISION이 다르면 검사 결과와 실행 이력이 분리됩니다.
CPU의 `EVT0_ML4_DEV00` POST eco03은 결과 미수신 예시입니다.
운영 검사 결과의 원천은 VWP에서 전송한 데이터입니다. 대시보드는 수신 결과를 조회·검토하며,
검사 실행이나 PASS/FAIL을 생성·편집하지 않습니다. 이 데모는 미리 준비된 예시를 사용합니다.
PoR 지정과 검토는 브라우저 메모리에만 저장되며 새로고침·초기화 시 돌아갑니다.
실제 VWP·EDA·SSO·DB 호출이나 운영 데이터 변경은 없습니다.

GCA 예시는 `/?demo=1&dataset=gca` 또는 데모 배너의 **GCA 예시 보기**에서 엽니다.
Atlas/Boreal 두 가상 프로젝트, 프로젝트별 CPU/GPU/DDR 네 블록, 다섯 실행의
`CLK_0003`, `CAS_0003`, `CLK_0026`, `EXD_0012`, `B2T_CAS_0001` 사례를 제공합니다.
프로젝트·블록을 선택한 뒤 실행과 sanity item을 고르면 예시 보고서 전체·출처·`.rpt`
다운로드를 확인할 수 있습니다. 같은 이름의 블록도 프로젝트와 실행별 검토 이력을 분리합니다.
PASS와 report 미도착 상황을 포함하며 AI 분류는 실제 호출하지 않습니다.

자료는 [Synopsys GCA 백서](https://www.synopsys.com/content/dam/synopsys/implementation%26signoff/white-papers/GCA_wp.pdf)
(2010, pp. 2, 6–8)와 [PrimeTime GCA User Guide 공개 열람본](https://www.scribd.com/document/807828202/PrimeTime-GCA-User-Guide-2016)
(Synopsys, L-2016.06, Chapter 2 / Example 2-8 / Appendix A)을 참고했습니다.
문서의 검사 의미와 규칙 번호를 참고하되 객체·수치·판정·보고서 문구는 데모용으로 구성한 예시 데이터입니다.
vendor report 전체나 이미지를 복제하지 않았으며, native report 형식·현행 버전의 규칙 호환·
실제 파서·DB·AI 연동 검증 자료로 사용하지 않습니다. 규칙별 묶음은 동일 원인 확정이 아닙니다.
프로젝트·블록 선택은 이 데모의 예시 탐색 기능이며 운영 API의 범위 관리 구현을 뜻하지 않습니다.

화면에서 접수 목록과 실행을 선택하고, 전체 점검 대장·문제 그룹·원문 예시·생략 수를
확인할 수 있습니다. 사람의 판단은 현재 개정과 요청 UUID를 함께 제출합니다.
실패한 명령을 그대로 재시도하면 같은 UUID를 유지하고, 내용을 수정하면 새 UUID를
생성합니다. 개정 충돌 시 검토 창을 닫고 새로고침한 후 다시 검토해야 합니다.
FAIL을 PASS로 바꾸는 입력과 분석 미완료 항목의 검토는 비활성화하며 서버에서도 검증합니다.

추가 근거는 알려진 기록 ID를 직접 입력할 수 있으며 PASS 항목에서도 요청할 수 있습니다.
VWP 요청 처리 상태와 OA 응답 수신 상태를 따로 보여줍니다. OA에서 응답을 검증하여
`RECEIVED`로 처리한 뒤에만 근거 본문을 열 수 있습니다. 근거 수신은 사람의 승인과 별개입니다.
이력은 API가 반환하는 최근 50개 범위와 전체 개수를 표시하며 전체 기록은 서버에 보존됩니다.
검색과 필터는 현재 점검 대장 페이지에만 적용합니다.
위의 1,000개 report 미리보기에서는 현재 프로젝트/블록의 전체 범위에 먼저 검색·필터를 적용하고 페이지를 나눕니다.

브라우저 검증:

```sh
npx playwright install --with-deps chromium
SANITY_DASHBOARD_TEST_PORT=5188 npm run test:e2e
```

Playwright는 실제 Chromium에서 명시적 데모, 로그인과 토큰 비저장, API 실패,
UUID 재시도·개정 충돌, 읽기 전용, 판단 기록, 근거 요청·응답, 보고서 다운로드,
390px 모바일 화면을 확인합니다. 데모 및 API 모킹 기반 UI 테스트이며 실제 DB·API 통합
검증은 상위 프로젝트 테스트와 별도로 수행합니다. 실패한 검사의 캡처·trace는 `test-results/`,
결과 보고서는 `playwright-report/`에 생성됩니다.
기본 mock UI 검사는 브라우저 context별로 격리하고 가용 CPU 수에 따라 최대 4개 작업자로 병렬 실행합니다.
`SANITY_DASHBOARD_TEST_WORKERS=1 npm run test:e2e`로 직렬 실행하거나 1~16개를 명시할 수 있습니다.
실제 합성 DB를 공유하는 workspace·drag 설정은 직렬입니다.
1,000개 preview의 테스트는 미리 생성한 합성 스냅샷도 필요합니다. 테스트 포트를 지정하면 해당 디렉터리의 개발 서버를
새로 시작하고 종료하며, 다른 worktree의 기존 5173 서버와 섞이지 않습니다.

그룹별 분류 근거 V2에서는 선택 그룹의 로그 옆에서 AI/참고 엔진 제안과 대표 원본을 확인하고, `근거 수정`으로 분류 기준·대표 로그·수정 사유를 저장합니다.
이동/병합/분리로 바뀐 그룹은 근거 재검토가 필요합니다. `분류 확정 · 판정 시작`은 현재 개정의 유효한 미확인 초안을 일괄 채택하며 2단계로 진행합니다. 전체 메모는 선택 입력입니다.
구형 근거 미작성 자료는 이력을 유지하며 새 확정 전에 보완합니다. TOP은 조회만 가능합니다.
브라우저 회귀는 별도 합성 QA 서버에서 `npm run test:workspace`를 사용합니다. 외부 모델은 호출하지 않습니다.

## Shadcn Studio 검토 시안

`/studio.html`에서 승인한 Shadcn Studio 디자인을 별도로 확인합니다. `npm run dev`와
`npm run build` 모두 이 진입점을 제공하며, 빌드 결과는 기존 `dist/`에 포함됩니다.
예: `http://127.0.0.1:5173/studio.html`, 어두운 화면은 `/studio.html?theme=dark`입니다.

그룹 목록은 의미를 추측한 아이콘 대신 **순번·이름·로그 건수·검토 상태**를 표시합니다.
순번은 현재 합성 보고서의 원래 그룹 순서이며 검색과 상태 필터로 다시 매기지 않습니다.
고정 분류 사전이나 그룹의 의미를 나타내는 ID가 아닙니다.

프로젝트 맥락 / 그룹 / 로그·원문 / 판정·근거를 나란히 배치하고 모바일에서는 세로로
연결합니다. 검색·페이지·체크박스 선택·탭·검토 이력 시트·밝은/어두운 화면을 체험할 수 있습니다.
원본 도구 결과, 합성 AI 제안, 사람의 판정은 구분하며 보류는 완료로 집계하지 않습니다.
합성 5개 그룹·126개 로그만 사용하고 확정 내용은 탭 메모리에 저장되어 새로고침하면 초기화됩니다.
실제 API·SSO·DB·모델 호출은 없습니다. 운영 화면의 분류 편집·권한·개정·AI 연동을
대체하지 않는 독립 시안입니다. 시안의 Studio UI 컴포넌트는 실제 운영 화면에서도 사용하며,
시안 전용 합성 데이터·독립 다크 테마·레이아웃 CSS는 `studio.html` 진입점에 남겨 둡니다.
실제 화면은 `studio-system.css`의 공통 토큰과 `live-workbench.css`의 검토 레이아웃을 사용합니다.
실제 SSO 화면은 `/`와 `/api/*`, 독립 합성 앱은 `/workspace`와 `/workspace/api/*`를 사용한다는 기존 계약을 유지합니다.
UI 변경은 회사 AI 접속, 100,000건의 모델 처리 완료나 새로운 권한 승인을 의미하지 않습니다.
