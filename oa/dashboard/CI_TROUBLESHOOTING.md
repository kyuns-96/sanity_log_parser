# 프런트엔드 CI 민감정보 탐지 대응

## 판정 코드와 비밀값 구분

`PASS`, `FAIL`, `UNKNOWN`, `DEFER`는 검사·검토 결과를 나타내는 공개 도메인 값이다. 비밀번호나 인증 토큰이 아니며 API·DB·기존 이력과 공유하므로 탐지 오류를 해결하려고 이름을 일괄 변경하지 않는다.

문자열 기반 검사는 문맥을 해석하지 못해 판정 문자열 뒤에 콜론이 오는 삼항식을 자격증명 설정으로 오인할 수 있다. 실제 검사 도구와 규칙을 확인하기 전에는 원인을 확정하지 않는다. 로컬 빌드 성공과 해당 표현식 제거만으로 사내 CI 통과를 선언하지 않는다.

## 코드 작성 기준

- 판정값을 선택하는 분기는 읽기 쉬운 `if`/`else`로 작성한다. 정상 판정 문자열을 삼항식의 참 분기에 직접 쓰고 바로 콜론을 잇는 표현은 피한다.
- 같은 결과를 원문·집계·표시에 사용하면 의미가 분명한 상태 변수로 한 번 계산해 재사용한다. 상태 변수에는 `sourceStatus`, `checkStatus`, `initialConclusion`처럼 목적을 나타내는 이름을 쓴다.
- `PASS` 등 전송·저장 값, 표시 이름·집계 키, 빈 그룹·미해석 결과의 의미는 유지한다. 자격증명 관련 변수는 실제 의미를 숨기려고 이름을 바꾸지 않는다.
- 문자열 분할·인코딩·주석 억제나 검사 도구 비활성화로 탐지를 우회하지 않는다. 실제 비밀값이면 코드 표현식 변경으로 해결하지 않고 승인된 비밀 관리·교체 절차를 따른다.
- 문서·예제·테스트에도 문제가 된 삼항식 원문을 다시 복사하지 않는다. 공개 설명에는 일반적인 원인과 수정 원칙만 남긴다.

그룹 원본 판정은 다음과 같이 표현한다.

```ts
let sourceStatus = 'UNKNOWN'
if (members.some(record => record.check_status === 'FAIL')) {
  sourceStatus = 'FAIL'
} else if (members.length > 0 && members.every(record => record.check_status === 'PASS')) {
  sourceStatus = 'PASS'
}
```

빈 그룹은 UNKNOWN, FAIL이 하나라도 있으면 FAIL, 비어 있지 않고 전부 PASS이면 PASS다. 그 밖의 혼합·미확인 결과는 UNKNOWN으로 유지한다.

이 원칙은 `WorkspacePipeline`, `WorkspaceReview`, 기존 검토 대장과 합성 데이터 생성에도 적용한다. 검사 예외가 필요하면 담당자의 승인 절차를 따르며 이 문서가 예외나 보호 파일 수정 권한을 부여하지 않는다.

## 수정 후 확인

`oa/dashboard`에서 `npm run build`로 타입과 빌드를 확인하고 변경한 흐름의 기존 브라우저 테스트만 실행한다. 분기 계산을 변경했다면 빈 입력·전부 정상·실패 포함·미확인 혼합의 결과를 확인한다. 저장/API 판정값이나 기존 테스트 기대값을 바꾸지 않는다. 이후 해당 CI를 다시 실행해 탐지 결과를 확인한다.

계속 실패하면 공개 가능한 도구·규칙 이름, 저장소 상대 파일 경로·줄 번호, 비식별 오류 코드만 전달한다. 실제 계정·내부 주소·비밀값·인증 자료·전체 CI 로그는 공개 저장소나 커밋 메시지에 넣지 않는다. 사내 AI는 [문의 규칙](../../INTERNAL_AI_GUIDE.md#6-디버깅이-필요하면-codex에게-문의)에 따라 중단하고 공통 코드 수정은 Codex에게 맡긴다.
