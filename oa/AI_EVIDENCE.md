# 사용자가 선택하는 AI 참고 근거

2026-11-02 사용자 결정. 사람의 분류·판정과 근거는 검토 이력으로 저장하며, **사용자가 등록한 근거만 다른 보고서의 AI 참고 사례로 제공**한다. 이전의 확정 시 자동 후보화 방침을 대체한다. 새 기록과 기존 미선택 기록 모두 기본 미등록이다. `reusable`·`compatible_versions`와 규칙 예외 여부를 등록값으로 사용하지 않는다.

## 화면 동작

- 선택 그룹의 근거 영역에 **분류 근거 AI 등록** 스위치를 표시한다. 확인한 그룹별 분류 기준만 등록한다. 전체 분류 확정 전의 검토 완료 근거는 선택을 보관하고, 전체 확정 후에 참고 후보가 된다.
- 현재 저장된 판정 위에 **판정 근거 AI 등록** 스위치를 표시한다. 현재 확정 그룹의 PASS/FAIL 판정과 이유만 등록하며 DEFER·미저장·변경 전 판정은 참고 대상으로 등록하지 않는다.
- 분류 근거에는 짧은 요약과 상세 설명을 함께 보관할 수 있다. 요약도 등록한 그룹의 지식에 포함하며 요약을 편집하면 새 내용의 등록을 다시 선택한다. 요약이 없는 기존 기록의 화면 발췌는 저장/등록 내용을 변경하지 않는다.
- 두 스위치는 독립적이다. 꺼짐은 왼쪽·미등록, 켜짐은 오른쪽·등록됨으로 표시한다. 서버 저장 응답을 받은 뒤 위치를 바꾸고, 저장 중에는 중복 조작을 막는다. 클릭·Space/Enter와 좌/우 방향키를 지원하며 OS의 애니메이션 감소 설정도 따른다.
- 근거 내용을 수정하거나 그룹의 이름/구성원을 바꾸면 이전 선택을 새 내용에 자동 적용하지 않는다. 다른 그룹만 바뀌고 해당 그룹의 원문·이름·구성·분류 근거가 같으면 선택은 유지할 수 있지만 전체 확정 전에는 후보로 사용하지 않는다. 새 판정 개정은 다시 등록을 선택한다.
- 등록 해제는 새로운 AI 참고를 중지한다. 작성한 근거·사람 확정·기존 제안과 감사 이력은 보존한다. 등록 여부만 변경해 사람의 판정/분류 개정을 새로 만들거나 무효화하지 않는다. 원본 삭제는 별도 [버전/보고서 삭제](WORKSPACE_RUNS.md)를 사용한다.

현재 판단 대상의 전체 로그와 해당 그룹의 분류 근거는 기존 입력 계약에 따라 제공한다. 이 스위치는 과거 지식을 다른 보고서의 AI에 공급할지 선택하는 기능이다. 원문 공개나 자동 PASS·규칙 실행 승인을 뜻하지 않는다.

## 서버와 검색 계약

`/api/workbench/blocks/{block}/versions/{version}/reports/{report}/groups/{group}/evidence/{CLUSTER|REVIEW}`에서 GET으로 상태를 읽고 POST로 변경한다. POST 본문은 `{enabled, expected_revision, binding_sha256, request_id}`만 받는다. SSO·Origin/요청 보호·현재 블록 OWNER를 검사하고, 최신 저장 내용의 binding과 선택 개정을 다시 확인한다. 브라우저에서 사용자 ID·근거 내용·공유 대상 목록을 지정하지 않는다. 응답 유실 시 같은 UUID로 확인하며, 새 상태 조회도 제공한다.

기존 `WS_CONFIG`에 별도 불변 선택 이력 `ai-evidence-choice-v1`을 저장한다. 내용 대신 대상·binding hash·선택값·actor·시각·개정만 기록한다. 기존 100자 키 제약 안에서 저장하며 DDL/GRANT를 추가하지 않는다. 보고서/버전 삭제 시 관련 선택과 요청 이력도 삭제한다.

AI 검색은 등록된 현재 유효한 근거를 기존 전역 공유 범위에서 찾는다. 분류 사례에는 선택한 그룹의 이름·근거만 넣고 미선택 그룹·전체 보고서 메모는 포함하지 않는다. 과거 원문·파싱 필드·전체 evidence ID 제외와 원문 API의 RBAC는 유지한다. 등록 해제/내용 변경/선택 개정 변경은 작업의 고정 사례 재검증에 반영하며 새 AI 결과를 적용하기 전에 차단한다. 기존 사람 확정 참조의 사실 유효성 검사와 새 입력의 등록 검사를 구분한다.

판정 사례에는 저장된 판정 근거·조건·예외와 그룹 출처를 제공한다. 판정 snapshot에 보관된 과거 분류 근거는 함께 전송하지 않는다. 분류 근거의 등록은 별도 스위치로 선택하며 분류 단계의 참고 사례로 사용한다.

OA 웹/프런트엔드와 중앙 VWP AI worker의 `oa/`·`common/`을 같은 릴리스로 맞춘다. 구형 worker는 등록 선택을 검사하지 못한다. 기존에 자동 후보화된 사례를 고정한 진행 작업은 새 정책에서 사례 검증에 실패할 수 있으며 미등록 근거로 결과를 적용하지 않는다. 등록 전환은 기존 원본·확정 이력을 일괄 수정하거나 회사 AI의 공통 코드 수정 권한을 넓히지 않는다.

사내 담당자는 자기 역할의 `run_tests.py --role oa|vwp-bridge`와 필요한 독립 mock의 같은 `--role`만 확인한다. 새 등록·API·검색/참조 경계는 `tests.test_ai_evidence_choices`, `tests.test_oa_ai_feedback`에서 합성 자료로 검증한다. 실제 모델 품질/속도와 운영 배포는 별도 현장 확인이다.
