# item별 AI 입력 필드 선택

2026-10-30 사용자 결정으로, AI에는 item에 선언한 필드만 전송할 수 있다. **모든 레코드를 처리**하는 계약은 유지하되 모든 원문 필드를 모델에 보내야 한다는 기존 조건은 명시된 정책에 한해 대체한다. 원본 report·전체 파싱 결과·위치·해시는 DB에 그대로 보존한다. 기존 승인·권한·인용 검증과 사람 확정 절차도 유지한다.

## 선언 위치와 예시

VWP plan의 `inventory.units[]`에 다음 선택 키를 넣는다. 기존 회사 입력 어댑터가 item별로 선언하며 공통 코드나 SQL을 바꿀 필요는 없다. 파서 등록 계약은 변경하지 않는다. 다음은 **합성 설정 예시**이며 실제 item의 필수 필드는 사내 담당자가 정한다.

선언을 추가하기 전에 VWP CLI·bridge·OA·VWP AI 작업자를 이 계약을 지원하는 같은 릴리스로 맞춘다. 이전 strict 수신기는 새 키를 거부할 수 있다.

```json
{
  "ai_fields": ["code", "scenario", "instance_message", "object"],
  "include_raw": false,
  "include_details": false
}
```

- `ai_fields`: `record.fields`에서 전송할 키 1~256개. 중복·공백·제어 문자·100자 초과 키를 거부한다. 미선언하면 모든 fields를 보낸다. 경로 표현식이 아닌 정확한 최상위 필드 이름이다.
- `include_raw`: `record.raw` 전송 여부. 미선언 기본값은 `true`다. `false`면 원문은 DB에만 남는다.
- `include_details`: 레코드 최상위 부가정보(줄/byte 위치·도구 상태·이유 등) 전송 여부. 미선언 기본값은 `true`다. `fields` 내부의 `details`라는 필드에는 적용하지 않으며 그 필드는 `ai_fields`가 선택한다.

세 키를 모두 생략하면 기존 요청 형식·프롬프트를 유지한다. 하나라도 선언하면 선택 정책을 적용하고, 레코드마다 반복되는 기술적인 원본 ID·hash 대응 정보는 서버에 남긴다. `include_raw: false`만 선언하면 fields 전체는 전송된다. 선언은 결과와 OA 보고서까지 존재 여부·타입·값을 대조하며 전달한다. 기존 보고서를 직접 고치지 않고 새 제출·분석 개정으로 적용한다.

## 판단과 원본 연결

분류와 그룹 판정의 단일·배치 요청에 같은 선택 정책을 적용한다. 레코드 수와 순서는 줄이지 않는다. 서버가 짧은 요청별 ID를 원본 레코드에 연결하고, 모델의 배정·인용이 제공된 범위 안에 있는지 검증한 뒤 원본 ID로 복원한다. 과거 사례·승인 기준·보존 본문의 인용은 별도 계약이다. 보존 본문 분할의 전체 coverage와 중간 통합 결과의 판단 근거는 이 옵션으로 잘라내지 않는다.

정책은 `ai-input-fields-v1`로 버전 관리하고 source/job pin·실제 요청 hash·프롬프트 버전에 연결한다. 정책이나 원본이 달라지면 이전 작업을 새 입력으로 이어 붙이지 않는다. 완료 배치를 보존하는 재개·UNKNOWN 복구도 같은 검사를 받는다. 미선언 과거 작업에는 새 투영을 적용하지 않는다.

선택한 키가 없는 레코드는 없는 상태를 그대로 표시한다. null·false·빈 문자열을 서로 바꾸거나 누락 값을 채우지 않는다. 제공할 fields와 raw가 모두 없는 레코드는 호출 전에 거부한다. AI에는 **전체 레코드의 제공된 필드**를 검토했다고 설명하도록 하고, 생략된 원문을 읽었다고 주장하지 않게 한다. 판단에 필요한 조건이 없으면 미확인 또는 DEFER로 남긴다.

## 적용 확인

사내에서는 합성 형식부터 원본 수·해시 보존, 실제 요청의 허용 필드·raw/details 제외, 인용 복원을 확인한다. 실제 item에는 코드·실행 조건·대상·수치·예외 등 필요한 의미 필드를 선정하고, 이전 전체 입력과의 분류/판정 품질·전송 bytes·응답 시간·호출 수를 비교한다. 전송량 감소는 속도 향상 실측 결과가 아니다. [한 작업 내 병렬 호출](PARALLEL_BATCHES.md)은 별도 선택 설정으로 함께 사용할 수 있다. 상수 hoist는 아직 구현하지 않았다.

내부 AI는 기존 입력 어댑터와 전용 합성 테스트 범위에서 선언을 추가한다. 공통 모델·worker·DB·UI 수정 권한과 오류 시 `WAITING_FOR_CODEX` 규칙은 확대하지 않는다.
